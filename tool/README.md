# KOBO

ヒアリング入力からWebサイトを生成する自社制作基盤。設計は `../docs/11-自社ツール設計_KOBO.md`。

利用者は1人。**過剰に作らない。** 実案件で3回困ったら作る。

## 現在の状態

v0.1 開発中。`lib/schema.ts`（ヒアリング項目の定義）のみ実装済み。

## 開発

```
npm install
npm run typecheck
```

## 設計上の原則

1. **`lib/schema.ts` が単一の正。** フォームUI・バリデーション・生成プロンプト・
   テンプレートの型はすべてここから導出する。仕様を二重管理した瞬間に壊れ始める。
2. **生成物は原稿の第1稿であって、商品ではない。** 人間のレビュー工程を飛ばさない。
3. **ヒアリングデータに出典のない事実は書かせない。** `collectFactTokens` と
   `BANNED_PHRASES` は機能ではなく安全装置。製造業の技術情報で嘘を書くと取引事故になる。

## ディレクトリ

```
lib/schema.ts   ヒアリング項目の定義（単一の正）
projects/       案件データ。案件IDごとのディレクトリ（Git管理しない）
```

## 注意

`projects/` には顧客の非公開情報（取引先、技術情報、連絡先）が入る。
**`.gitignore` で除外している。コミットしないこと。**
