# KOBO

ヒアリング入力からWebサイトを生成する自社制作基盤。設計は `../docs/11-自社ツール設計_KOBO.md`。

利用者は1人。**過剰に作らない。** 実案件で3回困ったら作る。

## 使い方

### 必要なもの

**Node.js 22.18 以降**（LTS版で問題ありません） → https://nodejs.org/

型ストリッピングで `lib/*.ts` を直接読むため、**ビルド手順はありません。**
**ヒアリングフォームは依存パッケージなしで動きます**（工場のネットは不安定なため、オフラインで動く必要がある）。
原稿生成のみ Anthropic SDK とネット接続が必要ですが、こちらは工場ではなく机の上で動かすものです。

### 起動：Finderから `start.command` をダブルクリック（いちばん簡単）

`tool/start.command` をダブルクリックすると、最新のコードを取ってきて起動します。
**ターミナルでフォルダを移動する必要はありません。** 終わるときは Control + C。

サイトの書き出しは `tool/build-site.command` をダブルクリック。案件を番号で選べます。

> 初回だけ「開発元を確認できないため開けません」と出ることがあります。
> その場合は**右クリック →「開く」**を選ぶと、以降は普通に開けるようになります。

### 起動：ターミナルから

```
git clone https://github.com/hirotakemura/Eclipse-restudy.git
cd Eclipse-restudy/tool      # ← ここに移動していないと npm は動きません
npm install     # 初回のみ。TypeScriptの型検査用で、起動自体には不要
npm start       # → http://localhost:5173
```

> **`Could not read package.json: /Users/あなた/package.json` と出たら、移動できていません。**
> `cd ~/Eclipse-restudy/tool` のように、`tool` の中まで入ってから実行してください。
> 置き場所が分からなくなったら：`find ~ -maxdepth 3 -type d -name "Eclipse-restudy"`

ブラウザで http://localhost:5173 を開き、**「＋ 新規案件」**から始めてください。
案件IDは英数字とハイフン（例: `matsubara-seiki`）。

> Node のバージョンが足りない場合は、起動時に何をすればよいか日本語で表示されます。
> 22.6〜22.17 なら `node --experimental-strip-types server.mjs` で動きます。

### タブレットで使う

取材は工場で立ったまま行う可能性があるため、**タブレット前提で作っている。**

- iPad縦（768px）以下は1カラム。ブロック一覧は横スクロールのチップ列になる
- **本文は16px。** iOS Safariは16px未満の入力欄をタップすると画面を勝手に拡大するため
- タップできるものは44px以上

タブレットから開くアドレスは、**`npm start` したときに表示される。** 調べる必要はない。

```
KOBO v0.2

  このパソコン       http://localhost:5173
  タブレット・スマホ http://192.168.1.23:5173
```

### 反映されているか確かめる

**「pull したのに変わっていない気がする」はよく起きます。** 版が2か所に出るので照合してください。

```bash
npm start          # → 「KOBO v0.2 （コード 8d607b5）」と出る
git rev-parse --short HEAD   # → 8d607b5 と一致するか
```

画面でも**フッターの右端**に出ています。

| 症状 | 原因 |
|---|---|
| 起動時の表示が変わらない | **サーバーを再起動していない。** `Control + C` で止めて `npm start` |
| 画面だけ古い | ブラウザのタブを閉じて開き直す（iOSのSafariは頑固なことがある） |
| フッターの版が古い | `git pull` がまだ。または別のフォルダで起動している |

> **フォーム項目（`lib/`）の変更は、サーバーを再起動しないと反映されません。**
> 起動時に1度だけ読み込むためです。画面まわり（`public/`）は再読み込みだけで反映されます。

### ⚠ 取材先のWi-Fiに繋いだまま使わないこと

このサーバーは**同じ網にいる端末から誰でも開けます。** 案件データには顧客の技術情報・
取引先・連絡先が入っているので、**取材先のゲストWi-Fiに繋いだまま開くと、他社の案件まで同じ網から見えます。**

タブレットを使うときは、**母艦のインターネット共有（テザリング）にタブレットを繋ぐ**のが安全です。
母艦だけで使うなら `localhost` なので、この問題は起きません。

### 取材で使うときの流れ

1. 「＋ 新規案件」で案件を作る。**会社名は未入力でよく、案件IDは自動で入る**（どちらも後から変更できる）
2. 左のブロックを上から順に進む。**各項目に取材台本の質問文が出る**ので、それを読み上げる
3. 答えてもらえなかった項目は**「未確認」**を押す。その場の発言を控えておける
4. 入力は約0.7秒後に自動保存される。**保存ボタンはない**
5. 案件を消すときは、フッターの**「この案件を削除」**。
   **すぐには消えず `projects/.trash/` に移動する**ので、間違えたら Finder から戻せる
5. 右上の**消化率が100%**になれば、聞き漏らしはゼロ

## 現在の状態

**v0.2 — 原稿生成と事実検証（実装完了・API鍵があれば動作）**

```
npm run test:verify              # 事実検証のテスト（API不要）
npm run generate -- <案件ID>     # 原稿生成（ANTHROPIC_API_KEY が必要）
```

- `lib/verify.ts` … **事実検証の安全装置。** 生成原稿の数値・型番・認証が案件データに
  出典を持つかを照合する。**検出率100%・誤検出0%**（`npm run test:verify` で確認できる）
- `lib/generate/` … ページ構成の決定・プロンプト・生成パイプライン。
  ページ単位で生成し、検証で弾かれたら指摘を添えて書き直させる

> **照合の対象に `unconfirmedNotes` を含めないこと。**
> ここには「ミクロン単位までは可能です」のような、**答えてもらえなかった記録**が入っている。
> これを出典として認めると、まさに捏造を防ぎたかった項目が素通りする。

**v0.1 — ヒアリングフォーム（完了）**

**フォームは商品ごとに分かれている。**案件を作るときにどちらかを選ぶ。

| フォームセット | 商品 | 規模 |
|---|---|---|
| `manufacturing` | 製造業向け 980,000円 | 7ブロック・60項目・想定90分 |
| `general` | 汎用ベーシック 198,000円 | 5ブロック・28項目・想定30分 |

**汎用フォームで製造業の案件を受けないこと**（D-048）。対応材質・精度・設備型番が無く、技術ページが作れない。

- 取材台本（`../docs/06-取材台本.md`）の構成をそのまま実装（製造業フォーム）
- 各項目に**台本の質問文を表示**。取材中はこれを読み上げながら埋める
- 入力のたびに自動保存（約0.7秒後）。90分ぶんの入力を失わない
- **「未確認」マーク**で、聞き漏らしと「答えてもらえなかった」を区別する

## 2つの充足率を分けている理由

| | 意味 | 目標 |
|---|---|---|
| **充足率** | 実際に値が入っている必須項目の割合 | 85%以上 |
| **消化率** | 充足＋「未確認」マークの割合＝**聞いた項目の割合** | 100% |

**「答えてもらえなかった」と「聞き忘れた」は全く別の問題です。**
前者は生成側で `{{要確認}}` を残せば済みますが、後者は取材のやり直しになります。

未確認マークの付いた項目について、**生成側は数値・型番・固有名詞を絶対に補完しません**（D-013）。

## 設計上の原則

1. **`lib/schema.ts` と `lib/form-definition.ts` が単一の正。** フォームUI・バリデーション・
   生成プロンプト・テンプレートの型はすべてここから導出する。二重管理した瞬間に壊れ始める。
2. **取材台本が仕様書。** 台本を変えたら `form-definition.ts` も必ず合わせて変える。
3. **生成物は原稿の第1稿であって、商品ではない。** 人間のレビュー工程を飛ばさない。
4. **ヒアリングデータに出典のない事実は書かせない。** `collectFactTokens` と
   `BANNED_PHRASES` は機能ではなく安全装置。製造業の技術情報で嘘を書くと取引事故になる。

## ディレクトリ

```
lib/schema.ts               案件データの型定義（単一の正）
lib/form-definition.ts      フォームの型定義とフォームセットの一覧
lib/forms/manufacturing.ts  製造業向けフォーム。取材台本の実装
lib/forms/general.ts        汎用フォーム
lib/completion.ts           充足率・消化率の計算
server.mjs               ローカルサーバー（依存パッケージなし）
public/                  フォームUI
fixtures/                検証用の架空企業（Git管理する）
projects/                案件データ（Git管理しない）
```

## 注意

`projects/` には顧客の非公開情報（取引先、技術情報、連絡先）が入ります。
**`.gitignore` で除外しています。コミットしないこと。**
