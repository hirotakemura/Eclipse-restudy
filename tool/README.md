# KOBO

ヒアリング入力からWebサイトを生成する自社制作基盤。設計は `../docs/11-自社ツール設計_KOBO.md`。

利用者は1人。**過剰に作らない。** 実案件で3回困ったら作る。

## 使い方

### 必要なもの

**Node.js 22.18 以降**（LTS版で問題ありません） → https://nodejs.org/

型ストリッピングで `lib/*.ts` を直接読むため、**ビルド手順はありません。**
外部の依存パッケージもゼロなので、**ネット接続なしで動きます**（工場のネットは不安定なため）。

### 起動

```
git clone https://github.com/hirotakemura/Eclipse-restudy.git
cd Eclipse-restudy/tool
npm install     # 初回のみ。TypeScriptの型検査用で、起動自体には不要
npm start       # → http://localhost:5173
```

ブラウザで http://localhost:5173 を開き、**「＋ 新規案件」**から始めてください。
案件IDは英数字とハイフン（例: `matsubara-seiki`）。

> Node のバージョンが足りない場合は、起動時に何をすればよいか日本語で表示されます。
> 22.6〜22.17 なら `node --experimental-strip-types server.mjs` で動きます。

### 取材で使うときの流れ

1. 取材の前に「＋ 新規案件」で案件を作る
2. 左のブロックを上から順に進む。**各項目に取材台本の質問文が出る**ので、それを読み上げる
3. 答えてもらえなかった項目は**「未確認」**を押す。その場の発言を控えておける
4. 入力は約0.7秒後に自動保存される。**保存ボタンはない**
5. 右上の**消化率が100%**になれば、聞き漏らしはゼロ

## 現在の状態

**v0.1 — ヒアリングフォーム（完了）**

**フォームは商品ごとに分かれている。**案件を作るときにどちらかを選ぶ。

| フォームセット | 商品 | 規模 |
|---|---|---|
| `manufacturing` | 製造業向け 980,000円 | 7ブロック・60項目・想定90分 |
| `general` | 汎用ベーシック 198,000円 | 5ブロック・28項目・想定30分 |

**汎用フォームで製造業の案件を受けないこと**（D-048）。対応材質・精度・設備型番が無く、技術ページが作れない。

- 取材台本（`../docs/06-取材台本.md`）の構成をそのまま実装（製造業フォーム）
- 各項目に**台本の質問文を表示**。取材中はこれを読み上げながら埋める
- 入力のたびに自動保存（約0.7秒後）。90分ぶんの入力を失わない
- **「未確認」マーク**で、聞き漏らしと「答えてもらえなかった」を区別する

## 2つの充足率を分けている理由

| | 意味 | 目標 |
|---|---|---|
| **充足率** | 実際に値が入っている必須項目の割合 | 85%以上 |
| **消化率** | 充足＋「未確認」マークの割合＝**聞いた項目の割合** | 100% |

**「答えてもらえなかった」と「聞き忘れた」は全く別の問題です。**
前者は生成側で `{{要確認}}` を残せば済みますが、後者は取材のやり直しになります。

未確認マークの付いた項目について、**生成側は数値・型番・固有名詞を絶対に補完しません**（D-013）。

## 設計上の原則

1. **`lib/schema.ts` と `lib/form-definition.ts` が単一の正。** フォームUI・バリデーション・
   生成プロンプト・テンプレートの型はすべてここから導出する。二重管理した瞬間に壊れ始める。
2. **取材台本が仕様書。** 台本を変えたら `form-definition.ts` も必ず合わせて変える。
3. **生成物は原稿の第1稿であって、商品ではない。** 人間のレビュー工程を飛ばさない。
4. **ヒアリングデータに出典のない事実は書かせない。** `collectFactTokens` と
   `BANNED_PHRASES` は機能ではなく安全装置。製造業の技術情報で嘘を書くと取引事故になる。

## ディレクトリ

```
lib/schema.ts               案件データの型定義（単一の正）
lib/form-definition.ts      フォームの型定義とフォームセットの一覧
lib/forms/manufacturing.ts  製造業向けフォーム。取材台本の実装
lib/forms/general.ts        汎用フォーム
lib/completion.ts           充足率・消化率の計算
server.mjs               ローカルサーバー（依存パッケージなし）
public/                  フォームUI
fixtures/                検証用の架空企業（Git管理する）
projects/                案件データ（Git管理しない）
```

## 注意

`projects/` には顧客の非公開情報（取引先、技術情報、連絡先）が入ります。
**`.gitignore` で除外しています。コミットしないこと。**
