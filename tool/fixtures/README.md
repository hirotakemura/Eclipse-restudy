# 検証用の案件データ（架空）

**ここにあるのはお客様のデータではありません。**【架空】有限会社 松原精機 という
練習用の会社で、第1回モック取材（`docs/15`）で作ったものです。

## なぜ Git に入れているのか

実際の案件データ（`tool/projects/`）は**お客様の非公開情報なので、絶対にコミットしません**。
ところがそのせいで、次の2つが起きていました。

1. **`npm test` が、Git管理外のファイルを読んでいた。**
   新しく clone した環境ではテストが動かず、案件を消せば壊れる状態だった
2. **社長とアドバイザーで、同じ「松原精機」を見ているつもりで中身が違った。**
   見た目（配色・メニュー）も別々なので、画面の話が噛み合わなくなる

架空の会社なので、ここに置けば両方とも解決します。

## 使い方

```
npm run demo          → projects/demo/ を作り直す（お客様の案件には触りません）
npm run build:site -- demo
npm run preview:site -- demo
```

**`projects/demo/` は毎回作り直されます。** ここで何を触っても、
ご自分の案件（`projects/<案件ID>/`）には影響しません。

## わざと壊してあります

このデータには、**公開前の検査に引っかかる欠陥がわざと残して**あります。

- 設備の「ABC123」と「現地で銘板と照合して確定させること」（D-169）
- 「メーカー・型番とも未確認」
- 強み・技術の「具体的な数値は工場長に要確認。」
- 写真がすべて仮の画像（D-174）

`npm run build:site -- demo` が「公開できません」で止まるのが**正しい動き**です。
検査そのものを確かめるための材料なので、直さないでください。
