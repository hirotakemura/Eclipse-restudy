# 引き渡しパッケージ — お問い合わせフォームの受け口

**このフォルダは、サイトを他社へ移すとき、または我々が事業を終えたときに使います。**

サイトの表示（HTML・CSS・画像）は、どこに置いても動きます（D-106・D-119）。
**動かないのはフォームの送信だけ**です。ここが、その置き換えです。

---

## 何が入っているか

| ファイル | 置き場所 | 役割 |
|---|---|---|
| `api/inquiry.php` | サイトの `/api/inquiry.php` | お問い合わせを受けて、メールで送る |
| `.htaccess` | サイトの一番上（`index.html` と同じ階層） | `/api/inquiry` を上のPHPに回す |

**サイトのHTMLは1文字も変えません。** フォームの送信先は `/api/inquiry` のままです。

---

## 移す手順（エックスサーバーなどの一般的なレンタルサーバー）

```
① サイトのファイル一式をアップロードする
② このフォルダの api/inquiry.php を  /api/inquiry.php  に置く
③ このフォルダの .htaccess を  /  に置く
④ api/inquiry.php の冒頭「ここだけ書き換える」4行を直す
      $TO        通知先のメールアドレス
      $FROM      差出人（そのサーバーのドメインに合わせる）
      $SITE_NAME 会社名
      $SITE_TEL  電話番号
⑤ ブラウザでフォームから1件送り、**通知先に届くことを目で確かめる**
```

**⑤を飛ばさないでください。** フォームは、止まっても画面にエラーが出ません。
「届かないだけ」なので、**送った側は届いたと思ったまま**になります。

---

## 元の仕組み（Cloudflare Pages を使っていたとき）

| | |
|---|---|
| 受け口 | `functions/api/inquiry.ts`（書き出したフォルダの中に入っています） |
| 送信 | Resend（**お客様名義のアカウント**・D-177①） |
| 環境変数 | `RESEND_API_KEY` / `INQUIRY_TO` / `INQUIRY_FROM` / `SITE_NAME` / `SITE_TEL` |

Resend を使い続けることもできます。その場合は `api/inquiry.php` の `$RESEND_KEY` に鍵を入れてください
（鍵はお客様名義のアカウントのものです。我々は持っていません）。

---

## 受け取っている項目

**PHP版もこの6つだけです。増やしていません。**

| 欄 | 必須 | 備考 |
|---|---|---|
| `name` お名前 | ○ | |
| `company` 会社名 | | |
| `email` メールアドレス | △ | 電話とどちらか必須 |
| `tel` お電話番号 | △ | 同上 |
| `subject` ご用件 | | |
| `body` お問い合わせ内容 | ○ | 4000文字まで |

ほかに、画面に出ていない `website` と `t` があります。**迷惑送信を止めるための欄**で、
`website` が埋まっていたら、また開いてから3秒未満の送信なら、受け付けません。
**外部の画像認証は使っていません。** 使うと、移した先でもそれを用意することになるからです。

### 図面の添付は受け付けません（D-179）

図面は**お客様の取引先の機密**です。自動返信メールに
「このメールにそのまま添付してご返信ください」と書いてあります。
**機密が当事者の間から出ませんし、移管するものも増えません。**

---

## 動いているかを確かめる

制作会社側では、次のコマンドで確かめられます（`tool/` で実行）。

```
npm run check:inquiry -- https://example.co.jp           送信せずに、受け口が生きているか見る
npm run check:inquiry -- https://example.co.jp --send    本物を1件送る（月次の点検）
```

移管後は、**フォームから1件送って、通知先に届くことを目で確かめる**のが確実です。
