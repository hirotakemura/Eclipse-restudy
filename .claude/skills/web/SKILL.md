# WEB制作担当

**受け持ち：** 承認済みの掲載文と案件データを受け取ってから、サイトが公開され、移管されるまで。
**受け持たない：** 取材の項目・掲載文の中身（→ `/kobo`）、お客様とのやり取り・契約（→ `/eigyo`）。
掲載文の言い回しが気になったら直さずに `/kobo` の保留に書く。**見た目の側で文を削ったり言い換えたりしない**（D-339「表現は、理由なく内容を消してはいけない」）。

## 最初に読むもの

1. `docs/38-保留中の作業.md` の「WEB制作」の節（待っているもの）
2. 触る場所の設計書——骨格 `docs/32`、表現と内容 `docs/33`（原則C）、余白と文字 `docs/34`、装飾と動き `docs/35`、素材 `docs/31`（原則①〜⑥・原則A/B）、生成ビジュアル `docs/36`（プロンプトの4節・見えるところに置く）、動きの設計案 `docs/37`（**未実装**）
3. 直す箇所の決定を `docs/04` で探す（`grep "D-4" docs/04-意思決定ログ.md` のように番号で引く。**全部は読まない**）

## よく使うコマンド（`tool/` で実行）

```
npm run build:site -- <案件ID>            公開用に書き出す（検査に落ちたら site-draft/ に回して止まる）
npm run build:site -- <案件ID> --draft    下書きとして書き出す
npm run preview:site -- <案件ID>          書き出したサイトを見る（http://localhost:4321）。file:// で開かない（D-113）
npm run variants -- <案件ID> --only 型,型  型を変えて2〜3通り書き出す（D-472）
npm run preview:variants -- <案件ID>      見比べ画面（--lan でタブレットから）
npm run demo                              架空の松原精機で、誰の環境でも同じ画面を出す（D-185）
npm run qa:visual / qa:assets / qa:visible / qa:contrast / qa:directions   見た目の検査（画面を撮る）
npm run dns -- <ドメイン>                 DNSの控えを取る（切り替えの前に必ず・D-122）
npm test                                  全部の検査
```

## 見た目の確認は、画面を見るまで終わらない（2026-09-17・社長のご指示）

**コードの上で正しく置かれていることと、人が実際の画面で認識できることは、別の話である。**

この案件で実際に起きたこと——

| 言っていたこと | 実際 |
| --- | --- |
| `placed 4`（4枚とも配置された） | **2枚は画面に出ていなかった**（型によって帯が取られていた） |
| `opacity .22` で敷いている | **最大画素差 4/255。人には形として見えていなかった** |
| キャプチャを撮って確認した | **スクロールが届いておらず、目的の帯が写っていなかった**（`scroll-behavior: smooth`） |
| 画素差を測って基準を決めた | **アニメーション途中で撮っており、実際の35%の値だった** |

どれも「実装上は存在する」ことの証拠であって、「視覚的に成立している」ことの証拠ではなかった。

### 順序（この順で行う。飛ばさない）

```
1. コード上の配置・DOM・CSS を確認
2. 実際のブラウザでそのページを表示
3. 対象が画面に入るよう正確にスクロールし、**到達したことを確かめる**
4. PC・SP それぞれでキャプチャを取得
5. **キャプチャ画像を実際に目視する**
6. 数値を測る
7. 画像を根拠に総合判断する
8. 問題があれば、**直す前に**原因と選択肢を報告する
9. 社長の承認なしにデザインを変更しない
```

### キャプチャなしで合格にしてはいけないもの

最初の画面（hero）／視覚的な山（peak）／生成ビジュアル／graphic／素材ライブラリ／
背景装飾／モーション／PC・SPの見え方／文字とビジュアルの重なり／焦点（focal point）／
切り取り（crop）／視覚のリズム／**段落ち（値や見出しが意図せず2行に折れること）**

### 禁止する言い方

次の推論だけで視覚の確認を終えない。

- 「CSS上は正しいので問題ない」
- 「opacity が .25 なので十分見えるはず」
- 「画素差があるので見えている」
- 「placed 4 なので4枚とも表示されている」
- 「DOMにあるので表示されている」
- 「プロンプトで焦点を指定しているので焦点も見えている」
- 「PCで見えるのでSPでも問題ない」
- 「この型で見て問題ないので、ほかの型でも問題ない」（D-472：目次が側面の型だけ段落ちしていた）

### 実物を確認できないとき

**社長と同じ画面を見られない場合は、推測して「問題なし」と報告しない。**

> この環境では実際の表示状態を確認できないため、PC/SP のキャプチャを送ってください

と依頼する。キャプチャをいただいたら、**その画像を見てから**判断する。

### 報告の形

```
■ コード上
  配置：○ ／ DOM：○ ／ CSS：○

■ 実画面（キャプチャを根拠に）
  配置：○△× ／ 視認性：○△× ／ 構図：○△× ／ 文字干渉：○△× ／ PC/SP差：○△×

■ キャプチャ
  PC hero / PC strength / PC peak / PC company
  SP hero / SP strength / SP peak / SP company
```

**キャプチャを取得できないときは「未確認」と書く。○ にはしない。**

### 撮り方で過去に誤ったこと（撮る前に確かめる）

- ブラウザは `tool/lib/browser.mjs` の `launchChromium()` で起動する。**開発環境のパスを直書きしない**（D-393）。無ければ「未確認」。
- `reducedMotion: "reduce"` で撮る。**動きの途中で撮らない**（D-400）。遅延読み込みの画像は読み込みを待つ。
- 毎回まっさらな窓で撮る（D-309）。走り出しの1枚は捨てる（D-321）。
- 見たい帯までスクロールしたら、**その帯が画面に入っていることを数値で確かめてから**撮る。
- はみ出しは**ページの横スクロールだけでなく、`overflow: hidden` の枠の中**でも測る（D-469）。
- 書き出したCSSは圧縮で書き換わる（`::before`→`:before`、`[a="b"]`→`[a=b]`、`alt=""`→`alt`、`min-width:761px`→`width>=761px`）。**書き出したHTML/CSSを正規表現で測るときは、書き換わった形で探す。**
- 撮った画面はGitに置かない（D-328）。検査票（人が見た記録）は残す。

## 作りの約束（いま効いているもの）

**テンプレートと値の置き場所**
- テンプレートは1つだけ（`tool/site-template/`・D-096）。案件ごとにコードを分けない。
- 見た目の選択肢は `tool/lib/theme.ts` が単一の正（D-138・D-197）。型は製造業6・汎用9で、プランごとに別の集合（D-198）。
- 文字の大きさは `--font-size`／`--measure` だけで変える（17・18・20px・D-153）。散文の1行は40字まで（D-154）。
- 同じ数字をCSSとTSの2箇所に置いたら、ずれたら落ちる検査を添える（D-197。例：`DECOR_PX` と書き出したCSSの突き合わせ）。

**構成**
- 構成はデータが決める（`lib/design/`・D-180）。サイトの骨格は `composeSite` が単一の正（D-331）。
- 内容の「本体」は1ページに決め、ほかのページは参照と導線にする（D-410）。写真と絵にも本体のページがある（D-445・D-454）。
- 中身の無いページは作らない（D-134）。事例が1件なら一覧の帯を出さない（D-341）。
- 最初の画面は「文字の列」と「判断材料の列」の2列（D-448。絵の列は D-463 で撤回し、絵は背景）。右の列は値を大きく組む（D-451）。
  値の段は `fitInRow` で欄の数から決め（D-455）、**入らないときだけ列の実幅まで縮める**（D-472）。

**素材と絵**
- 素材を置かないことは失敗ではない（`docs/31` 原則①）。穴を埋めるために素材を探しにいかない。
- 生成ビジュアルは**背景として敷く**（列にしない・D-459・D-463）。文字の下は地で守る（D-405）。
- 絵の明暗は注文書の言葉と書き出しの検査の両方で見る（D-464）。**来歴が「未確認」の絵は書き出すが公開しない**（D-465）。
- 写真の大きさは役割で決める（D-444）。1枚だけの写真を決まった比率に押し込まない（D-436・D-440）。
- 白抜きの帯（暗い地・アクセント地）は1ページに1回だけ、その会社を一言で言う帯に当てる（D-230・D-231）。

**文字と色**
- コントラストは宣言ではなく描画で測る（D-359・`qa:contrast`）。リンクを色だけで区別しない（D-158）。
- ヘッダーのロゴの横に会社名を出す。**ロゴに社名が入っている会社では出さない**（D-460・D-462）。

**動き**
- 動きは増やさない。`docs/37` は設計案で**未実装**。実装する前に社長に確認する。

## 公開の関門（`build-site.mjs` が止めるもの）

次のどれかが残っていると、`site/` ではなく `site-draft/` に書き出して止まる（D-112）。**関門を外して通さない。**
- 会社名・電話番号・所在地・問い合わせの通知先が無い／仮の写真が残っている（D-174）
- 未確認マーカー・未確認欄の控え・社内向けの欄の中身・社内語がページに出ている（D-169・D-170）
- 人が承認していない掲載文・取材の言葉に無い記述（D-466・D-381。**中身の判断は `/kobo`**）
- 案件データにあるのに写真のファイルが無い（D-428）／来歴が未確認の生成ビジュアル（D-465）

**止めないが、毎回目で確かめるもの：** 取材で「出さない」とお約束したもの（`terms.ngItems`）は書き出しのたびに一覧で出る。
**機械では判定しない**ので、ページを開いて出ていないことを見る（D-427）。

## 見比べと、原稿のご確認（D-472）

原稿のご確認で、**中身の入ったサイトを2〜3通り**お見せして選んでいただく（取材では決めない・D-471）。
前日までに `variants --only` で書き出し、見比べ画面を**PCとスマホの両方の幅で目視**しておく。
型を並べたときにだけ出る崩れがある（目次の位置で列の幅が変わる）。当日の進め方は `/eigyo`。

## 公開と移管

- 置き場所は Astro の静的書き出し ＋ Cloudflare Pages（D-009）。**WordPress には対応しない**（D-085）。
- DNS の切り替えは `docs/20` の手順どおり。**控え（`npm run dns`）を取るまで始めない**（D-122）。TTLは1週間前に300秒へ（D-123）。
  ネームサーバーの変更はお客様ご本人に操作していただく。IDとパスワードは預からない（D-124）。
- 既存ドメインでは MX（メール）を先に全件控える（D-107）。
- 引き渡すのは公開しているサイトの静的ファイル一式。KOBO・テンプレートは渡さない（D-119）。
