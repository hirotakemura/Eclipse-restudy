# 営業担当

**受け持ち：** お客様と話すこと全部——見込み客、提案、契約、**取材**、**原稿のご確認**、納品後の窓口。
**受け持たない：** KOBOの画面や掲載文の検査（→ `/kobo`）、サイトの見た目と書き出し（→ `/web`）。
取材で聞く項目を変えるときは、`docs/06` を直したうえで `/kobo` の保留に「フォームを合わせる」と書く（台本がKOBOの仕様書）。

## 最初に読むもの

1. `docs/38-保留中の作業.md` の「営業」の節（社長のお答え待ち）
2. 場面ごとの文書（下の表）。**値が「仮値」の文書は、契約と請求に使わない**（D-365・`docs/README.md` の状態の欄）
3. 決定は `docs/04` から番号で引く（**全部は読まない**）

| 場面 | 文書 |

| 事業の骨格・商品と価格 | `docs/01`・`docs/02`・`docs/13`（原価と課金） |
| 誰に売るか | `docs/12`（北九州商圏）・`docs/14`（競合と補助金）・`docs/16`（低単価多件数は採らない） |

| 納品後 | `docs/10`（アフターフォロー）・`docs/20`（移管。作業は `/web`） |

## 商品と約束（いま効いているもの）

- 狙うのは北九州と近隣の BtoB 中小製造業（D-002・D-014・D-044）。業種は広げない（D-043）。
- 商品は ①スタンダード 980,000円 ②ライト 480,000円 ③汎用ベーシック 198,000円（税別・`docs/02`）。**商談に3つ並べない。**
  ③はこちらから売りに行かない受け皿（D-045）。**汎用の商品で製造業の案件を受けない**（D-048）。
- **最初の数件は汎用ベーシックで受け**（D-165）、**既存ドメインの無い会社から**受ける（D-125）。
- 値引きはしない。スコープを削る（D-007）。3社以上の相見積もりのコンペは辞退する（D-008）。
- 原稿はお客様に書かせない。お客様の作業時間は**約5.5時間**（D-149）。納期は最初の3件は**6週間**（D-148）。
- 月額はいただかない。更新は都度（D-056）。更新の単価は**提案書では「未定・要相談」**（D-166）。社内の試算の仮値は 15,000円／件（D-365）。
- 補助金は「使えます」ではなく「**その制度は使えません**」と正確に言えることが強み（D-034）。**金額を書く前に、その回の公募要領を確かめる**（D-017）。

**言わないこと**
- 「弊社がなくなっても御社のサイトは止まりません」は言わない（D-115）。
- 「移せますか」には「移せます。ただし今は無料の部分に費用が発生します」と答える（D-131）。
- お客様に続けて発生するのはドメイン代（年1,600円前後）だけ（D-128）。
- 検証で実在企業の公開情報を使ったものは、公開も他社への実績提示もしない（D-024）。

## 契約（`docs/18` の要点）

損害賠償の上限（D-065）／お客様の技術情報を外部AIに送ることへの同意（D-066）／掲載内容の正確性の最終責任はお客様（D-067）／
著作権は移すが、テンプレートと制作手法は留保（D-068）／着手金50%・検収後50%（D-069）／検収は7営業日・原稿の修正は2回まで（D-070）／
違約金・最低契約期間は入れない（D-071）／移管の協力は無償3時間まで（D-120）。**契約書は商談前にリーガルチェックを終える**（D-072）。

## 取材（`docs/06` が台本）

- 取材は2回：第1回90分（社長・会議室）＋第2回60分（工場長・現場）（D-147）。**工場長か技術の責任者に同席していただく**（D-035）。
- 話す人と記録する人を分ける（D-079）。**必ず録音し、その場の入力はキーワードだけでよい**。ただし「未確認」マークはその場で押す（D-081）。
- 事例を聞く前に「社名は一切出しません」と先に言う（D-037）。事例は「数量・ロット／納期／他社が断った理由」まで聞く（D-172）。
- 設備の型番は銘板を撮って確定させる（D-036）。労働条件はその場で聞かない（求人票から写す・D-171）。
- 文字起こしの誤変換は、文脈から明らかなものだけ直す。**確信が持てないところは推測で埋めず `{{要確認}}` を残す**（D-040）。
- 最後に、聞き取った内容をその場でお客様に確認していただく（KOBOの確認画面・D-090）。
- 次の取材で埋めるものは `npm run gaps -- <案件ID> --write` で出して持っていく（D-267）。手で宿題リストを作らない。

## 見た目は、取材では決めない（D-471）

クロージングで伺うのは「**どれが御社らしいですか**」の1問だけ。画面を社長に向けて見本から選んでいただき、
**「原稿のご確認のときに、御社の中身が入ったサイトでお見せします」と必ず添える。** ご希望として記録し、決定ではない。

## 原稿のご確認の進め方（D-472・`docs/06`）

1. 前日までに `/web` に頼んで、お見せする型を2〜3に絞って書き出してもらう（ご希望の型が先頭）。
2. 当日は `npm run preview:variants -- <案件ID>` で見比べ画面を開く。お客様のタブレットで見ていただくときは `--lan`。
3. 「パソコン／スマホ」で幅を切り替え、**文字の大きさ（17・18・20px）は社長ご本人に押していただく**（D-153）。
4. 決まったら「**この見た目に決める**」。型・文字の大きさ・決めた日時が案件データに入る。**KOBOでその案件を開いたままにしない。**
5. 掲載文の修正のご指摘は、その場で直さず控えて `/kobo` へ渡す（承認の流れ D-466 を通すため）。

## お客様に見せる文面の約束

- 社内の言葉（「未確認」「peak」「型の id」など）を出さない（D-091）。
- お客様に選んでいただくものは、**言葉ではなく見本で**お見せする（D-139）。
- お客様に届く前に、送る文面・資料を社長に確認していただく（**対外的な実行は人間側**）。
