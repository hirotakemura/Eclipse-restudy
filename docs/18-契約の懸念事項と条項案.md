## 2. 特に重要な3つ

### ① 損害賠償の上限を必ず入れる（C-3）

**これがないと、98万円の案件で数千万円を請求されうる。**

我々は `10-インフラとアフターフォロー方針.md` で
**「フォームの疎通監視は絶対に外さない」**と自分で約束しています。約束した以上、
**フォームが止まって大口の引き合いを逃した場合、因果関係を主張される余地があります。**

製造業の1件の引き合いは、年間数百万〜数千万の取引になりうる（`01` 第2章）。
**つまり、我々が提案書で強調している「1件の引き合いの価値が大きい」という話が、
そのまま賠償額の主張根拠になります。**

```
【条項案】
第◯条（責任の制限）
　乙の責任は、故意または重過失による場合を除き、
　本件業務に関して乙が甲から受領した対価の総額を上限とする。
　乙は、逸失利益・機会損失・間接損害について責任を負わない。
```

**副業で始める以上、ここは妥協できません。**

### ② 顧客の技術情報を外部AIに送ることへの同意（E-1）

**これは、製造業の顧客が最も嫌がることです。**

我々の制作フローは、取材で得た情報（**対応材質・加工法・精度・設備型番・工程の工夫・治具の内製**）を
Claude API に送って原稿を生成します（`11-自社ツール設計_KOBO.md`）。

**これは、その会社のノウハウそのものです。**

> 「うちの工程がAIに学習されるのか」

これを無断でやって後から発覚したら、**信用は一度で終わります。**
北九州の中小製造業は横の繋がりが強い（`12` 第3章）ので、その話は確実に広まります。

**先に説明し、同意を取る。そして正確に説明する。**

```
【条項案】
第◯条（制作ツールの利用と機密情報の取扱い）
1. 乙は、本件業務の遂行にあたり、原稿作成のために外部のAIサービスを利用する。
2. 乙が利用するサービスは、入力された情報を当該サービス提供者の
　 モデルの学習に使用しない設定で運用する。
3. 乙は、甲が第◯条に基づき開示不可と指定した情報を、前項のサービスに入力しない。
4. 甲が本条の利用を望まない場合、甲はその旨を書面で申し出ることができる。
　 この場合、乙は納期の延長を求めることができる。
```

> **第3項が実務上の肝です。** 取材時に「出せない情報」を確認する工程は既にあります
> （`06` ブロック6／フォームの `terms.ngItems`）。**そこで挙がったものはAIにも入れない。**
> これなら、口先だけでなく**運用として守れます。**
>
> 第4項は正直な逃げ道です。どうしても嫌だという顧客には、手作業で書きます。時間はかかりますが。

**【要確認】** Anthropic の API がデフォルトで入力を学習に使わないことは、
**契約前に一次情報で裏を取ってください。** 説明が事実と違うと、条項そのものが無効になります。

### ③ 掲載内容の正確性の最終責任は顧客にある（A-4）

**我々が書く商品だからこそ、必要です。**

「±5μm」と書いたサイトを見て発注が来たが、実際は±20μmしか出せなかった——
これは**顧客と発注元の取引事故**です。原稿を書いたのは我々ですが、**情報の出どころは顧客**です。

```
【条項案】
第◯条（掲載内容の確認）
1. 乙は、甲への取材に基づき原稿を作成する。
2. 甲は、納品前に掲載内容を確認し、承認するものとする。
　 掲載内容（特に技術仕様・数値・認証等）の正確性については、甲が最終的な責任を負う。
3. 乙は、甲が確認・承認した内容について責任を負わない。
```

> **我々の側の担保は既に実装済みです。**
> ヒアリングデータに出典のない数値・型番は生成しない（`tool/lib/schema.ts` の `collectFactTokens`）、
> 答えてもらえなかった項目は `{{要確認}}` を残す（D-013）。
> **「勝手に書いていない」ことを技術的に証明できる状態にしてあります。**

## 3. その他の主要な条項案

### 検収と修正回数（A-1／A-2）

```
第◯条（原稿および検収）
1. 原稿の修正は2回までを本件対価に含む。3回目以降は別途見積もる。
2. デザイン確定後のデザイン変更は、別途見積もる。
3. 乙が検収を依頼した日から7営業日以内に甲から書面による指摘がない場合、
　 検収は完了したものとみなす。
4. 公開後30日間に限り、誤字脱字および表示不具合の修正を無償で行う。
```

> **第3項がないと、「返事が来ないまま3ヶ月」が起きます。** これは実際によくあります。

### 納期（A-5）

```
第◯条（納期）
1. 納期は、契約締結日から◯週間とする。
2. 甲の確認・素材提供が、乙の依頼から5営業日を超えて遅延した場合、
　 その超過日数だけ納期を延長する。
```

> **「4週間」という約束は、我々の側の努力だけでは守れません。** ここを書いておかないと、
> 顧客側の遅れで遅れた分まで我々の責任になります。
> なお、**実測で4週間に収まるかは準備期間で検証中**です（D-022）。
> **実測より良い数字を契約書に書かないこと。**

### 著作権（D-1）★重要

```
第◯条（著作権）
1. 本件成果物のうち、甲の事業内容を記述した原稿・写真・
　 甲専用のデザインに係る著作権は、対価の完済をもって甲に移転する。
2. 前項にかかわらず、乙が本件業務以前から有していた、
　 または汎用的に用いるプログラム・テンプレート・
　 コンポーネント・制作手法に係る権利は、乙に留保される。
3. 乙は、前項の留保された権利に基づき、他の業務において
　 同種の成果物を制作することができる。
```

> **第2項がないと、KOBOのテンプレート資産が最初の1件で顧客のものになります。**
> 「2件目以降の原価を下げる」という事業の前提（`02`）が、契約書1枚で崩れます。
> **ここは絶対に外さないでください。**

### 支払い（B-1／B-2）

```
第◯条（対価および支払）
1. 本件対価は◯◯円（税別）とする。
2. 甲は、契約締結後14日以内に対価の50%を、
　 検収完了後、当月末締め翌月末日までに残額を支払う。
```

> **着手金50%は、副業の規模では必須です。** 全額後払いで踏み倒されると、
> 年間の粗利が1件で消えます（製造業1件の粗利 634,500円・`01` 第3章）。
>
> 「翌々月末払い」を求められた場合は、**着手金の比率を上げる**（70%など）ことで対応します。
> **支払いサイトの長さ自体は、製造業の商慣行なので押し返しにくい。**

### 押し返されたときの譲歩の順番【後日相談・2026-09-12 保留】

**その場で考えると、たいてい一番譲ってはいけないところを譲ります。** 順番を先に決めておく。

```
　1段目　着手金30% ＋ 検収後70%　　　　　　　　　← まずここまで
　2段目　着手金30% ＋ 中間30% ＋ 検収後40%　　　← 分割を増やす。総額は変えない
　3段目　着手金なし ＋ 全額検収後　　　　　　　　← 継続取引の実績がある相手だけ
```

**値引きはしない。譲るのは支払いのタイミングだけ**（`07` 第2章の方針と同じ）。

> **この段数と線引きは、アドバイザーと後日あらためて相談する。**
> それまでは **着手金50%を既定**として条項案に置いておく。
> 実際に押し返されるかどうかは商談してみないと分からないため、
> **商談の感覚を持っている側（アドバイザー・友人）の判断を待つ。**

### 汎用商品（198,000円）の支払い

**分割しない。公開時に一括。**
金額が小さく、紹介経由で信用の下地があり、**分割の事務のほうが高くつく。**

### 実績としての公開（D-2）

```
第◯条（実績の公開）
1. 乙は、本件成果物を制作実績として、
　 甲の名称およびURLとともに公開することができる。
2. 甲が公開を望まない場合、契約締結時にその旨を申し出る。
```

> **「事前に断らなければ公開してよい」形にしておく**のが実務的です。
> 後から一件ずつ許可を取りに行くのは、現実には回りません。

### 無償提供とその終了（C-1／C-4／D-059）

```
第◯条（公開後のサービス）
1. 乙は、本契約に基づき、以下を無償で提供する。
　 ①サイトの死活監視 ②問い合わせフォームの疎通確認
　 ③ドメイン・SSL証明書の期限管理 ④月次レポートの送付
2. 前項は、乙が本事業を継続する限りにおいて提供する。
　 乙が本事業を終了する場合、90日前までに書面で通知し、移管に協力する。
3. サイトの内容変更・追加は前項に含まれず、都度見積もる。
4. 乙は、本事業終了後も3年間、
　 問い合わせフォームの送信に使用するドメインを維持する。
```

> **第4項は、なりすまし防止のためです**（`17` 第3章）。年1,500円で買える安心。

### 引き渡しの範囲と、移管への協力（D-1／2026-09-13 追加）

> **「ソース一式をお渡しします」の中身を決めておかないと、後で揉めます。**

```
　■ 引き渡すもの（検収・全額の支払い完了後）
　　　① 公開しているサイトの静的ファイル一式（HTML・CSS・JS・画像）
　　　② 原稿テキスト（全ページ）および元画像
　　　③ ドメイン・DNSの設定情報（レコードの全件と、移管の手順書）
　　　④ 引き継ぎ手順書

　■ 引き渡しに含まれないもの
　　　・弊社のヒアリングツールおよびサイト生成基盤
　　　・弊社が複数の顧客向けに用いるテンプレートのソース
　　　（①は、これらを用いずに他社が引き継げる形で引き渡します）

　■ 他社への移管に際しての協力
　　　・弊社は移管に協力し、違約金その他の請求は行いません
　　　・**無償での協力は合計3時間までとし、これを超える作業は
　　　　都度対応（有償）とします** ※単価は未定（要相談・D-166）
```

**なぜ「静的ファイル一式」なのか（顧客に説明する言い方）**

> 「公開しているサイトそのものをお渡しします。**どのサーバーにも置ける形**ですし、
> 次の業者さんも特別な準備なしにそのまま直せます。
> 弊社の制作ツールをお渡ししても、そちらを用意していただく手間が増えるだけですので。」

## 4. 契約書に「書かない」と決めたこと

| 項目 | 理由 |
|---|---|
| 違約金・解約金 | **取らない。**「気持ちよく終われることが次の事業の資産になる」（`17` 第8章） |
| 最低契約期間 | 月額を取らないので、そもそも期間の概念がない（D-056） |
| 競業避止（D-3） | **受けない。** 製造業特化である以上、競合同士の案件は必然的に発生する。<br>ただし**同一商圏で直接競合する場合は事前に相談する**運用にする（契約ではなく姿勢の問題） |

## 6. 進め方の提案

```
　① この叩き台をもとに、条項の方向性をアドバイザーと合意する　← 今ここ
　② 行政書士・弁護士にリーガルチェックを依頼（数万円）
　③ 修正して雛形を確定
　④ 初回の案件で使い、実務で困った点を反映して改訂
```

**②は、初受注が見えてから**で構いません。ただし**商談の前には終わっていること。**
見積を出した後に契約書で条件が変わると、**そこまでの信頼が一気に崩れます。**

> **北九州には商工会議所の無料法律相談があります**（`12` 第6章）。
> 会員になれば使えるはずなので、**スタート時のテクノセンター訪問とあわせて確認してください。**
