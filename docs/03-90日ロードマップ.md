# 準備期間3ヶ月計画（Day 1–90）

改訂: 2026-09-12（アドバイザーの方針により、最初の90日を「準備期間」として再定義）
前提: 週10〜20時間（副業）／北九州・BtoB中小製造業／アドバイザーを仮顧客としたドッグフーディング

## 0. この3ヶ月で何を証明するのか

ツールを作ることが目的ではありません。**提案書で顧客に約束した2つの数字を、実測で検証することが目的**です。

```
　　約束1　　納品まで 4週間
　　約束2　　お客様の作業時間 約4.5時間
```

この2つは `07-提案書テンプレート.md` の目玉であり、我々の商品そのものです。
**守れないなら、約束のほうを変えなければいけません。** それを商談で言ってしまう前に、自分たちで確かめる。

**3ヶ月の最大の成果物は、動くツールではなく「この2つの数字は守れる」という実測データです。**

## 1. 【最重要ルール】3ヶ月で区切る

> **Day 90 を過ぎたら、KOBOが未完成でも営業を開始する。未完成の部分は手作業で埋める。**

理由は2つあります。

**理由1：ツール開発は完璧を求めると無限に延びる。**
「あと少し便利にしたい」は永遠に湧いてきます。期限を切らないと、1年経ってもツールを作っています。

**理由2：準備が延びると、初入金が全部後ろにずれる。**

```
　準備3ヶ月 → 営業3ヶ月 → 制作1ヶ月 → 入金1ヶ月 ＝ 初入金は8ヶ月後
```

副業のため生活費の持ち出しは不要で、8ヶ月分の固定費（約33万円＋初期投資10万円）は
想定資金内に収まります。**資金的には問題ありません。**
ただし**準備が1ヶ月延びれば初入金も1ヶ月ずれる**ので、ここは厳守します。

### 「スタート」の定義（2026-09-12 追記）

アドバイザーの方針により、**対外的な手続きはすべて Day 90 の「スタート」時にまとめて実施**します。
3ヶ月を手続きで細切れにせず、**準備期間は作ることだけに集中する。**

```
　準備期間（Day 1–90）　　作ることに集中。対外的な活動はしない
　　　　　　　↓
　スタート（Day 90）　　　開業届・インボイス登録・簡易課税の届出
　　　　　　　　　　　　　商工会議所入会／テクノセンター訪問
　　　　　　　　　　　　　企業データベース確認 → リスト作成 → DM開始
```

**この順序で問題がないことを確認しました。**

| 懸念 | 確認結果 |
|---|---|
| インボイス登録のリードタイム | **e-Taxなら2〜3週間〜1ヶ月、書面なら1〜1.5ヶ月。** Day 90に申請すれば、初受注（Day 180頃）・初請求（Day 210以降）には十分間に合う。→ **必ずe-Taxで申請する** |
| 初入金の時期 | Day 90スタート → 営業3ヶ月 → 制作1ヶ月 → 入金1ヶ月 ＝ **8ヶ月後**。従来の見通しと変わらない |
| ターゲットリストの作成 | 企業DBの検索軸（業種・保有設備・所在地）が判明したため、**抽出条件は準備期間中に確定しておく**（`12` 第5章）。スタート時は条件どおり絞るだけにする |

### 例外：屋号だけは Day 61 までに決める

**屋号は手続きではなく判断**なので、スタート待ちにできません。
Month 3 で自社サイトを作るため、**ドメイン・メールアドレス・名刺がすべて屋号に紐づきます。**

社長推奨は `09-屋号候補.md` のとおり：

```
　屋号　　　　ものづくりウェブ
　タグライン　北九州の製造業専門のホームページ制作
```

**Day 61 までにご決定ください。** ここが決まらないと Month 3 が丸ごと止まります。

## 2. ドッグフーディングの設計

### 仮顧客は2種類つくる

**① メイン：架空の製造業1社を作り込む**

北九州の精密切削加工会社「**有限会社 松原精機**」（架空）を設定しました。
→ `tool/fixtures/mock-matsubara/profile.md`

アドバイザーがこの会社の社長役を演じ、私が取材台本どおりに90分の取材を行います。
**設定には意図的に「社長が即答できない項目」と「盛った表現」を仕込んであります。**
本番で必ず起きることを再現するためです。

**② サブ：実在企業の公開情報だけでフォームを埋める**

北九州の製造業3社を選び、**取材なしで、公開されているサイトとパンフレットの情報だけ**でフォームを埋めます。

これは手抜きのテストではありません。**情報が欠けている状態でKOBOが正しく `{{要確認}}` を出し、
事実を捏造しないかを確かめる**ためのテストです。本番でも「取材で聞き漏らした」は必ず起きます。

> **実在企業を扱う際のルール（厳守）**
> 1. **生成物は公開しない。** 社外に出さない
> 2. **他社への実績・ポートフォリオとして見せない。** 取引関係がないのに示唆することになる
> 3. 当該企業に見せる場合は「公開情報から勝手に作りました」と正直に伝える
> 4. あくまで内部の検証用。判断に迷ったら使わない

### 計測する指標（KOBOに組み込む）

「精度を高める」を感覚で終わらせないため、数字で追います。

| # | 指標 | 目標 |
|---|---|---|
| 1 | 取材90分で埋まった項目の割合 | **85%以上** |
| 2 | 生成原稿のうち、手直しなしで使えた割合 | **70%以上** |
| 3 | 事実誤りの検出率（意図的に誤りを混ぜて測定） | **100%**（安全装置なので妥協しない） |
| 4 | 制作の実工数（社長側） | 記録する |
| 5 | **顧客役の工数** | **4.5時間以内** |
| 6 | **着手から公開までの日数** | **28日以内** |

**指標3だけは目標未達を許容しません。** 事実の捏造は取引事故に直結します（D-013）。

## 4週目ごとのレビュー

- **毎週：** 進捗と、計測指標の記録
- **4週ごと：** 計画の修正 → `04-意思決定ログ.md` に反映

### 約束が守れなかった場合の対応（先に決めておく）

| 実測結果 | 対応 |
|---|---|
| 納期が28日を超えた | **提案書の「4週間」を実測値に書き換える。** 6週間なら6週間と書く |
| 顧客工数が4.5時間を超えた | 同じく実測値に書き換える。**または超過の原因を工程から取り除く** |
| 両方とも大きく超過 | **商品設計そのものを見直す。** 「早い・ラク」で売れないなら別の売りが必要 |

**実測より良く見せた数字を提案書に書かない。** 商談で言った数字は守ることになります。
