# 撤退と引き継ぎの設計

起案: アドバイザー（2026-09-12）
> 「副業なので、もし撤退する場合の対処法を決めておきたい。
> 　運用保守を月額で持つのではなく、都度対応で受けるほうがいいのか」

検討: 社長 / 結論: **都度対応で正しい。ただし、撤退時に顧客のサイトが止まる穴が設計に残っていた**

---

## 1. まず、都度対応が正しい理由（撤退の観点から）

| | 月額契約 | **都度対応** |
|---|---|---|
| 契約の性質 | **継続の約束** | その都度の取引 |
| 撤退時 | 解約手続き、場合により違約金の議論 | **未完了の義務が残らない** |
| 顧客への説明 | 「契約を終了させてください」 | 「今後は他社をご紹介します」 |

**月額を持たない事業は、いつでも止められます。** これは副業として始める以上、決定的に有利です。
→ **D-056（都度対応）の判断は、撤退のしやすさという観点からも支持される。**

### ただし、ひとつ抜けがあった

**無償で提供すると約束したもの**（死活監視・フォーム疎通テスト・期限管理・月次レポート）は、
契約上は無償でも、**顧客からすれば継続してもらえる前提のサービス**です。

**これは実質的な継続義務です。** 止めるときには説明が要ります。
→ 契約書に**終了条項**を入れます（第6章）。

---

## 2. 【重大】撤退したとき、顧客のサイトで何が止まるか

**現状の設計では、我々が消えると顧客のサイトが全部止まります。** これは設計の穴です。

| 要素 | 誰のアカウントか | 我々が消えると |
|---|---|---|
| ドメイン | **顧客名義**（D-011） | △ **ドメインは残るが、ネームサーバーが我々のCloudflareを指したままだと名前解決が止まる**（2026-09-13 訂正・`10` 2-2） |
| **DNS（Cloudflare）** | **我々** | **× 管理不能。放置すれば動くが、変更できない** |
| **ホスティング（Cloudflare Pages）** | **我々** | **× アカウント削除でサイトが消える** |
| **フォームのメール送信（Resend）** | **我々**（我々のドメインから送信・D-018） | **× 問い合わせが届かなくなる** |
| スパム対策（Turnstile） | 我々 | × フォームが動かなくなる |
| 死活監視（UptimeRobot） | 我々 | △ 監視が止まるだけ |
| **GA4 / Search Console** | **我々** | **× 過去のデータごと失われる** |

**残るのはドメインだけです。** これでは「ロックインしない」という提案書の約束（`07`）が、実態として守られていません。

---

## 3. 一番危険なのは、フォームのメール送信

`docs/10` 第3章で **「フォームの疎通監視は絶対に外さない。問い合わせが届いていなかったというのは、
我々が信用を失う唯一の事故」** と書きました。

**撤退すると、まさにその事故が全顧客で同時に起きます。**

しかも、より悪い問題があります。

> **我々のドメインが失効して第三者に取得されると、そのドメインから送られたメールが
> 顧客の問い合わせとして扱われ続けます。なりすましのリスクになります。**

### 対策：ドメインは事業終了後も最低3年維持する

**年1,500円です。** 粗利から見れば誤差であり、**最も安い保険**です。契約書にも書きます。

---

## 4. 「止まらない構造」にする（5つ）

完全に依存をなくすのはコストが見合いません。**依存は残しますが、止まっても致命傷にならない設計にします。**

### ① サイトに電話番号とメールアドレスを必ず併記する

**フォームだけに問い合わせ経路を依存させない。**

フォームが止まっても、電話とメールが載っていれば問い合わせはゼロになりません。
そもそも**中小製造業の社長は電話を使います**（`10` 第3章で更新依頼も電話で受けると決めた）。
**撤退耐性のためだけでなく、実用上も正しい。**

→ **全案件で必須にする。テンプレートに組み込む。**

### ② GA4 と Search Console は顧客名義で作り、我々が招待される

これは**今すぐ変えられます。** 我々のアカウントで作ると、撤退時に**過去のデータごと失われます。**
顧客名義なら、我々の権限を外すだけで済みます。

### ③ ドメインを事業終了後も3年維持する（第3章）

### ④ 納品時に「引き渡しパッケージ」を渡す（撤退時ではなく）

**撤退してから渡すのでは遅い。** 最初から渡しておきます（第5章）。

### ⑤ Cloudflare のアカウント情報を、事業主以外も持っておく

バス係数1の問題（第7章）。

---

## 5. 納品時に渡す「引き渡しパッケージ」

**公開の時点で、顧客が自走できる状態にしておきます。**

```
　① サイトのソース一式　　　HTML / CSS / JS / 画像。静的なのでどこにでも置ける
　② 原稿テキスト　　　　　　全ページ分。Markdown
　③ 元画像　　　　　　　　　加工前のデータも含む
　④ ドメイン・DNSの情報　　 レジストラ、ネームサーバー、**DNSレコードの全件エクスポートと戻し手順**
　⑤ 引き継ぎ手順書　　　　　「他社に引き継ぐときに、次の業者へ渡すもの」の一覧
　⑥ フォームの仕組みの説明　どこを変えれば自前に切り替えられるか
```

> **⑤と⑥が肝です。** これがあると「弊社がいなくなっても、次の業者がすぐ引き継げます」と
> **証拠をもって言えます。** 口約束ではなく、現物で示せる。

**この作成は制作工程に組み込みます**（`02` の制作フロー Week 4）。都度作ると必ず後回しになるためです。

---

## 6. 契約書に書くこと

```
　■ 成果物の帰属
　　　サイトのソース・原稿・画像は顧客に帰属する。公開時に一式を引き渡す。

　■ ドメイン
　　　顧客名義で取得する。弊社は管理を代行するのみ。

　■ 無償提供するサービスの終了
　　　死活監視・フォーム疎通テスト・期限管理・月次レポートは、
　　　弊社が事業を継続する限り無償で提供する。
　　　**終了する場合は90日前に書面で通知し、移管に協力する。**

　■ 事業終了後のドメイン維持
　　　弊社は事業終了後も、フォームの送信に使用するドメインを
　　　**3年間維持する。**（なりすまし防止）

　■ 保守の形態
　　　月額の保守料は発生しない。更新作業が生じた場合のみ、都度お見積りする。
```

**「90日前に通知」を自分で書いておくことが大事です。** 撤退を決めてから条件を考えると、必ず揉めます。

---

## 7. バス係数1への備え（撤退より起こりやすい）

**撤退は自分で決められますが、病気や事故は決められません。**

1人で他社のサイトを預かる以上、**事業主が動けなくなったときに顧客のサイトが人質になります。**
副業・1人体制では、撤退よりこちらのほうが現実的なリスクです。

| # | 備え |
|---|---|
| 1 | **パスワードマネージャを使い、緊急アクセス権を友人に設定する** |
| 2 | Cloudflare アカウントに友人をメンバー招待しておく |
| 3 | **「もしものときに誰が顧客に連絡するか」を決めて、友人と共有しておく** |
| 4 | 顧客リスト（連絡先・ドメイン・公開日）を、友人がアクセスできる場所に置く |

**友人が営業を担当する体制（D-051）は、この点でも効いています。** 事業を知っている人がもう1人いる。

---

## 8. 撤退の手順（先に決めておく）

```
　Day -90　全顧客に書面で通知。「90日後に無償提供を終了する」
　　　　　　あわせて、引き渡しパッケージの再送と、引き継ぎ先候補の紹介
　Day -60　希望する顧客のDNS・ホスティングを移管
　Day -30　移管状況の確認。未対応先に再連絡
　Day 0　　監視・レポートを停止。当社アカウントからプロジェクトを削除
　以降3年　送信ドメインのみ維持（なりすまし防止）
```

**違約金は取らないし、請求もしません**（`10` 第4章）。
北九州の中小製造業は横の繋がりが強く、**揉めた話は必ず広まります**（`12` 第3章）。
**気持ちよく終われることが、そのまま次の事業の資産になります。**

---

## 9. これは、そのまま営業の武器になる

出口設計を守りの話だと思っていましたが、逆でした。

> **「弊社が万一なくなっても、御社のサイトは止まりません。
> 　ソースも原稿もお渡ししてありますし、ドメインは御社名義です。
> 　次の業者さんがすぐ引き継げる状態にしてあります。」**

**これを証拠付きで言える制作会社は、そう多くありません。**

サイトを他社に作ってもらった中小企業が抱える不安の上位は、
**「あの業者と連絡が取れなくなったらどうなるのか」**です。
実際、それで困っている会社を営業先で見つけることになります（サイトが古いまま放置されている会社の一定数がこれ）。

`08-営業DM文面と想定問答.md` の「他社に乗り換えられます」という切り返しに、**この一段を足します。**

## 10. 決定

| # | 判断 |
|---|---|
| 1 | **都度対応を維持する**（D-056）。撤退のしやすさという観点からも正しい |
| 2 | **無償提供には終了条項を置く。** 90日前の書面通知と移管協力を契約書に明記 |
| 3 | **サイトに電話番号とメールアドレスを必ず併記する。** フォーム単独依存を避ける |
| 4 | **GA4・Search Console は顧客名義で作り、我々が招待される形にする** |
| 5 | **引き渡しパッケージを納品時に渡す。** 制作工程（Week 4）に組み込む |
| 6 | **事業終了後もドメインを3年維持する**（年1,500円。なりすまし防止） |
| 7 | **バス係数1に備える。** パスワードマネージャの緊急アクセス権を友人に設定 |
