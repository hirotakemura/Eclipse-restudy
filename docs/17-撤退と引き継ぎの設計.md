# 撤退と引き継ぎの設計

起案: アドバイザー（2026-09-12）
> 「副業なので、もし撤退する場合の対処法を決めておきたい。
> 　運用保守を月額で持つのではなく、都度対応で受けるほうがいいのか」

検討: 社長 / 結論: **都度対応で正しい。ただし、撤退時に顧客のサイトが止まる穴が設計に残っていた**

---

## 1. まず、都度対応が正しい理由（撤退の観点から）

| | 月額契約 | **都度対応** |
|---|---|---|
| 契約の性質 | **継続の約束** | その都度の取引 |
| 撤退時 | 解約手続き、場合により違約金の議論 | **未完了の義務が残らない** |
| 顧客への説明 | 「契約を終了させてください」 | 「今後は他社をご紹介します」 |

**月額を持たない事業は、いつでも止められます。** これは副業として始める以上、決定的に有利です。
→ **D-056（都度対応）の判断は、撤退のしやすさという観点からも支持される。**

### ただし、ひとつ抜けがあった

**無償で提供すると約束したもの**（死活監視・フォーム疎通テスト・期限管理・月次レポート）は、
契約上は無償でも、**顧客からすれば継続してもらえる前提のサービス**です。

**これは実質的な継続義務です。** 止めるときには説明が要ります。
→ 契約書に**終了条項**を入れます（第6章）。

---

## 2. 【重大】撤退したとき、顧客のサイトで何が止まるか

**現状の設計では、我々が消えると顧客のサイトが全部止まります。** これは設計の穴です。

| 要素 | 誰のアカウントか | 我々が消えると |
|---|---|---|
| ドメイン | **顧客名義**（D-011） | △ **ドメインは残るが、ネームサーバーが我々のCloudflareを指したままだと名前解決が止まる**（2026-09-13 訂正・`10` 2-2） |
| **DNS（Cloudflare）** | **我々**（※選択制・下記2-2） | **× 管理不能。放置すれば動くが、変更できない** |
| **ホスティング（Cloudflare Pages）** | **我々**（※同上） | **× アカウント削除でサイトが消える** |
| **フォームのメール送信（Resend）** | **我々**（我々のドメインから送信・D-018） | **× 問い合わせが届かなくなる** |
| スパム対策（Turnstile） | 我々 | × フォームが動かなくなる |
| 死活監視（UptimeRobot） | 我々 | △ 監視が止まるだけ |
| **GA4 / Search Console** | **我々** | **× 過去のデータごと失われる** |

**残るのはドメインだけです。** これでは「ロックインしない」という提案書の約束（`07`）が、実態として守られていません。

## 2-2. 【選択制】お客様名義のCloudflareアカウントに置く（2026-09-13 追記）

> **この選択肢は `10-インフラとアフターフォロー方針.md` 2-2 で決めたものですが、
> 撤退の文書に書いていませんでした。** 撤退の話を探すとここに無い、では意味がないので転記します。

**Cloudflareは無料プランでも、他のユーザーを管理者として招待できます**（公式ドキュメントで確認済み）。
つまり、**お客様名義でアカウントを作り（無料・クレジットカード不要）、我々が管理者として入る**形が取れます。

| | 我々のアカウント（既定） | **お客様名義のアカウント** |
|---|---|---|
| 撤退時にサイトは | **止まる**（我々のアカウント削除で消える） | **止まらない。** アカウントはお客様のもの |
| 撤退時の作業 | DNSの移管が要る | **ほぼ不要。**我々の権限を外すだけ |
| 我々の運用 | 1つの画面で全案件を見られる | **100件なら100アカウントを行き来する** |

### なぜ既定にしないのか

**運用が回らなくなったら、事業ごと止まります**（D-126）。週10〜20時間の副業で100件を
別々のアカウントで見るのは現実的ではありません。

### いつお客様名義にするか

```
　・お客様から「自社の管理下に置きたい」と求められたとき
　・撤退リスクを特に気にされているとき（上場企業の取引先が多い、など）
　・我々の側で、その案件だけ別扱いにしても回ると判断できるとき
```

**提案書・契約書にも「ご希望があればお客様名義で構築します」と書けます。**
言えること自体が営業上の武器になります（第9章）。

> **この形にした場合、ホスティングの費用は変わらず0円です**（Cloudflareの無料枠）。
> お客様に追加の負担は発生しません。

## 3. 一番危険なのは、フォームのメール送信

`docs/10` 第3章で **「フォームの疎通監視は絶対に外さない。問い合わせが届いていなかったというのは、
我々が信用を失う唯一の事故」** と書きました。

**撤退すると、まさにその事故が全顧客で同時に起きます。**

しかも、より悪い問題があります。

> **我々のドメインが失効して第三者に取得されると、そのドメインから送られたメールが
> 顧客の問い合わせとして扱われ続けます。なりすましのリスクになります。**

### 対策：ドメインは事業終了後も最低3年維持する

> **ここで維持するのは「我々の送信ドメイン」だけです。**
> **顧客のサイトを撤退後も維持する、とは決めていません**（第8章の手順では Day 0 に停止します）。
> 混同しやすいので明記します。

粗利から見れば誤差であり、**最も安い保険**です。契約書にも書きます。

#### 費用の根拠（2026-09-13 訂正）

当初「年1,500円」と書いていましたが、**一次情報で裏を取っていませんでした。**
調べ直すと、2026年9月時点のお名前.comで **.com 約1,622円／.jp 約1,605円（年・維持調整費込み）**です。

| | |
|---|---|
| 出典 | お名前.com の料金ページおよび比較記事（2026年時点） |
| 注意 | **維持調整費は1〜3ヶ月ごとに改定される。** 固定の数字として扱わない |
| **未確認** | **`co.jp` の維持費。** 中小企業は `co.jp` を使うことが多く、汎用ドメインより高い。契約書に金額を書く前に必ず確認する |

**3年で約5,000円**という規模感は変わらないので、判断（維持する）は変えません。

## 4. 「止まらない構造」にする（5つ）

完全に依存をなくすのはコストが見合いません。**依存は残しますが、止まっても致命傷にならない設計にします。**

### ① サイトに電話番号とメールアドレスを必ず併記する

**フォームだけに問い合わせ経路を依存させない。**

フォームが止まっても、電話とメールが載っていれば問い合わせはゼロになりません。
そもそも**中小製造業の社長は電話を使います**（`10` 第3章で更新依頼も電話で受けると決めた）。
**撤退耐性のためだけでなく、実用上も正しい。**

→ **全案件で必須にする。テンプレートに組み込む。**

### ② GA4 と Search Console は顧客名義で作り、我々が招待される

これは**今すぐ変えられます。** 我々のアカウントで作ると、撤退時に**過去のデータごと失われます。**
顧客名義なら、我々の権限を外すだけで済みます。

### ③ ドメインを事業終了後も3年維持する（第3章）

### ④ 納品時に「引き渡しパッケージ」を渡す（撤退時ではなく）

**撤退してから渡すのでは遅い。** 最初から渡しておきます（第5章）。

### ⑤ Cloudflare のアカウント情報を、事業主以外も持っておく

バス係数1の問題（第7章）。

## 5. 納品時に渡す「引き渡しパッケージ」

**公開の時点で、顧客が自走できる状態にしておきます。**

```
　① サイトのソース一式　　　HTML / CSS / JS / 画像。静的なのでどこにでも置ける
　② 原稿テキスト　　　　　　全ページ分。Markdown
　③ 元画像　　　　　　　　　加工前のデータも含む
　④ ドメイン・DNSの情報　　 レジストラ、ネームサーバー、**DNSレコードの全件エクスポートと戻し手順**
　⑤ 引き継ぎ手順書　　　　　「他社に引き継ぐときに、次の業者へ渡すもの」の一覧
　⑥ フォームの仕組みの説明　**受け取っている項目の一覧と、通知先メールアドレス**
　　　　　　　　　　　　　　 他社へ移すと送信部分は作り直しになるため、
　　　　　　　　　　　　　　 **次の業者が同じものを作れるだけの情報**を書いておく
```

> **⑤と⑥が肝です。** これがあると「弊社がいなくなっても、次の業者がすぐ引き継げます」と
> **証拠をもって言えます。** 口約束ではなく、現物で示せる。

**この作成は制作工程に組み込みます**（`02` の制作フロー Week 4）。都度作ると必ず後回しになるためです。

### 5-2. 「渡したものを持って他社へ行かれる」リスク（2026-09-13 追加）

アドバイザーからの問い：**納品時に一式を渡すと、他社に引き継いでから切られるのでは。**

その通りです。**起こります。** そのうえで、渡す方針は変えません。理由は4つです。

#### ① そもそも、ロックインで守れる事業ではない

**公開している静的サイトは、HTMLを取れば誰でも再現できます。** 半日から1日の作業です。
ソースを渡さなくても引き継ぎは止められません。
**弱い技術的な人質のために、営業上の最大の武器を捨てることになります。**

#### ② 我々の営業は「そうではない業者です」と言うことで成り立っている

`08-営業DM文面と想定問答.md` には、**「前の業者と連絡が取れなくなった」**への切り返しがあります。
渡さない方針にした瞬間、**その営業トークが嘘になります。**
北九州の中小製造業は横の繋がりが強く（`12` 第3章）、**揉めた話は必ず広まります。**

#### ③ 収益が前払いに寄っているので、離脱の痛みが小さい

**月額をいただかない設計（D-056）にした時点で、この問題は半分解けています。**

| | 金額 |
|---|---|
| 制作費（着手時・検収時に受領済み） | 980,000円 |
| 離脱で失うもの＝更新の都度課金 | 1回15,000円〜。年2〜3回として**年3〜4.5万円** |

**失うのは制作費の5%程度／年**です。サブスク型なら致命的ですが、我々の構造では致命傷になりません。

#### ④ 引き止められるのは、コードではなく「知っていること」

新しい業者は、**取材90分で得た情報をゼロから取り直さなければなりません。**
追い質問で出た強み（治具の内製など・`15`）、未確認として残した項目、出せない情報の線引き。
**これは渡したソースには入っていません。** ここが本当の乗り換えコストです。

だから、引き止めに使うのはロックインではなく次の3つです。

| | |
|---|---|
| 月次レポートを止めない | 原価ゼロ。接点が切れない（D-045） |
| 更新を頼みやすくする | 電話で受ける・48時間以内。**新しい業者はまずサイトの構造を読むところから** |
| 取材記録を持ち続ける | 2年目の追加取材・事例の追加を、こちらから提案できる |

---

### 5-3. 渡すもの・渡さないものを、契約書で分ける

**「ソース一式」の中身を決めておかないと、後で揉めます。**

| | 渡す | 理由 |
|---|---|---|
| 公開しているサイトの静的ファイル一式（HTML/CSS/JS/画像） | **渡す** | どこにでも置ける。**受け取る側にビルド環境を要求しないので、むしろ引き継ぎやすい** |
| 原稿テキスト・元画像 | **渡す** | 顧客の情報そのもの |
| DNSレコード全件と戻し手順 | **渡す** | これが無いと、ドメインが顧客名義でも戻せない（D-106） |
| **KOBO本体・Astroテンプレート・取材データベース** | **渡さない** | 我々の道具であって、納品物ではない |

> **正直に書くと、この線引きは我々の道具も守ります。**
> ただし「静的ファイルのほうが引き継ぎやすい」というのは本当で、
> Astroプロジェクトを渡すと、受け取った業者はビルド環境を用意しないと1文字も直せません。
> **顧客にとっても、そのほうが良いものを渡しています。**

### 5-4. 「やめます」と言われたときの手順

```
　① 違約金は取らない。請求もしない（`10` 第4章）
　② 移管に協力する。**無償は3時間まで**（DNS移管・アカウント権限の移譲・次の業者からの質問対応）
　　　　超えた分は都度課金（1時間 10,000円）
　③ 最後に一度だけ、理由を聞く。**改善の材料にする**
　④ ドメイン・GA4・Search Console の権限を外す。データは顧客名義なので残る
```

**②の上限を決めておかないと、終わった案件に無限に時間を取られます。**
副業（週10〜20時間）で回す以上、ここは先に決めておきます。

## 6. 契約書に書くこと

```
　■ 成果物の帰属
　　　サイトのソース・原稿・画像は顧客に帰属する。公開時に一式を引き渡す。

　■ ドメイン
　　　顧客名義で取得する。弊社は管理を代行するのみ。

　■ 無償提供するサービスの終了
　　　死活監視・フォーム疎通テスト・期限管理・月次レポートは、
　　　弊社が事業を継続する限り無償で提供する。
　　　**終了する場合は90日前に書面で通知し、移管に協力する。**

　■ 事業終了後のドメイン維持
　　　弊社は事業終了後も、フォームの送信に使用するドメインを
　　　**3年間維持する。**（なりすまし防止）

　■ 保守の形態
　　　月額の保守料は発生しない。更新作業が生じた場合のみ、都度お見積りする。
```

**「90日前に通知」を自分で書いておくことが大事です。** 撤退を決めてから条件を考えると、必ず揉めます。

## 7. バス係数1への備え（撤退より起こりやすい）

**撤退は自分で決められますが、病気や事故は決められません。**

1人で他社のサイトを預かる以上、**事業主が動けなくなったときに顧客のサイトが人質になります。**
副業・1人体制では、撤退よりこちらのほうが現実的なリスクです。

| # | 備え |
|---|---|
| 1 | **パスワードマネージャを使い、緊急アクセス権を友人に設定する** |
| 2 | Cloudflare アカウントに友人をメンバー招待しておく |
| 3 | **「もしものときに誰が顧客に連絡するか」を決めて、友人と共有しておく** |
| 4 | 顧客リスト（連絡先・ドメイン・公開日）を、友人がアクセスできる場所に置く |

**友人が営業を担当する体制（D-051）は、この点でも効いています。** 事業を知っている人がもう1人いる。

## 8. 撤退の手順（先に決めておく）

```
　Day -90　全顧客に書面で通知。「90日後に無償提供を終了する」
　　　　　　あわせて、引き渡しパッケージの再送と、引き継ぎ先候補の紹介
　Day -60　希望する顧客のDNS・ホスティングを移管
　Day -30　移管状況の確認。未対応先に再連絡
　Day 0　　監視・レポートを停止。当社アカウントからプロジェクトを削除
　以降3年　送信ドメインのみ維持（なりすまし防止）
```

**違約金は取らないし、請求もしません**（`10` 第4章）。
北九州の中小製造業は横の繋がりが強く、**揉めた話は必ず広まります**（`12` 第3章）。
**気持ちよく終われることが、そのまま次の事業の資産になります。**

## 9. これは、そのまま営業の武器になる

出口設計を守りの話だと思っていましたが、逆でした。

> **「弊社が万一なくなっても、御社のサイトは他社さんへすぐ引き継げます。
> 　ソースも原稿もお渡ししてありますし、ドメインは御社名義です。
> 　DNSの設定も控えをお渡ししてあるので、そのまま移せます。」**

> **【2026-09-13 修正】「サイトは止まりません」とは言いません。**
> ネームサーバーが我々のCloudflareを指したままだと、**ドメインが顧客名義でも名前解決は止まります**（D-106）。
> **言えるのは「止まっても、すぐ戻せる／引き継げる」までです。**
> 事実より強い約束をすると、その一点で全部の信用を失います。

**これを証拠付きで言える制作会社は、そう多くありません。**

サイトを他社に作ってもらった中小企業が抱える不安の上位は、
**「あの業者と連絡が取れなくなったらどうなるのか」**です。
実際、それで困っている会社を営業先で見つけることになります（サイトが古いまま放置されている会社の一定数がこれ）。

`08-営業DM文面と想定問答.md` の「他社に乗り換えられます」という切り返しに、**この一段を足します。**

## 11. この文書の根拠と、裏を取っていないもの（2026-09-13 追加）

アドバイザーからの問い：**「撤退後の維持は、どのソースを元に判断したのか」**

**正直に書きます。この文書の判断の多くは、一次情報で裏を取っていません。**
事業の約束（提案書・契約書に書く内容）に使う以上、どこが確かでどこが推定かを分けておきます。

| 主張 | 根拠 | 確からしさ |
|---|---|---|
| 顧客名義のドメインは、我々が消えても顧客のものとして残る | レジストラ契約が顧客名義であるという契約上の事実 | **確か。**ただしDNSは別問題（D-106） |
| 失効したドメインが第三者に取得され、なりすましに使われうる | 一般に知られた現象 | **確からしいが、具体の出典は未提示** |
| ドメインの維持費は年1,600円前後 | お名前.com の料金（2026年9月時点） | **確認済み。**ただし維持調整費で変動。`co.jp` は未確認 |
