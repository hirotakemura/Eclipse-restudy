## 今回やったこと：検証が走る状態の整備と、その途中で見つけた欠陥の修正

### 1. AI OFF を基準として固定した（D-223）

```bash
npm run qa:companies                        # AI OFF。基準と照合する
npm run qa:companies -- --ai-brief          # AI ON。基準との差分を出す
```

基準は `fixtures/design-diversity/baseline-ai-off.json`。

### 2. 「前回の差分5箇所」の内訳（ご指示の整理）

### 3. 検証の準備中に見つけた欠陥を直した（D-224・D-225）

**これが今回いちばん重要な発見です。**

ダミーのキーで報告の経路を通したところ、APIが401で落ちて規則版に戻した案件で、
**強みページと設備ページの帯が変わり、しかも `ai` の印が付いていました。**

```
  判断の出所：AI版→規則版に戻した
    strengths/index    **変わった**
        conditions:largeNumber:quiet  →  conditions:spec:lead　[ai]   ← これが出てはいけない
```

`ai-fallback` の中身は**規則版そのもの**です。渡しても渡さなくても同じでなければなりません。

原因は、Brief が「内容ごとに1つの値」を持つのに対し、
**同じ内容でもページによって出し方が違う**ことでした。
強みページの条件の帯は「強みを読んだあとに確かめてもらう」控えめな帯で、
対応可能範囲のページでは主役です。Briefはその区別を持てません。

直し方は2つ入れました。

1. **採用されなかった Brief（`rules` / `ai-fallback`）は構成に効かせない**（D-224）
2. **Brief が効くのはトップページだけにする**（D-225）。
   AIが決めるのは「何を主役にするか」で、それはトップページの話です

いまは401でも**全ページ変化なし**になります。

> **なぜ前回の試験を通り抜けたか。**
> トップページの**表現だけ**を見て、**強さ（emphasis）も下層ページも見ていなかった**からです。
> 試験を「全ページ・強さ込みで1文字も変わらないこと」に直しました。
> 見ていないものは、通ります。

## 人間が評価するための材料

キーが用意でき次第、この3点を画面で見比べていただきます。
数値だけで「良くなった」と判定しない、というご指示に沿って、
**AI自身に理由は書かせません**（そもそも文章を返す欄がありません）。

| fixture | project.json の材料 | 確認したいこと |
|---|---|---|
| A precision | `capability.tolerance` = ±0.005mm（短く言い切れる・数字を含む） | **largeNumber が本当に妥当か。** 規則版は `conditions:spec` を選んでいます（最初の画面がすでに数字なので、すぐ下で同じ形を繰り返さないため・D-183）。AIが largeNumber を選ぶなら、この規則を超える根拠が要ります |
| B difficulty | `strengths.wonAfterOthersDeclined` に他社様が断った案件の記録。**鍵括弧つきの発言は事例側にあり** | **quote / process を主役にすることが妥当か。** 規則版は `declined:quote` を主役、事例を `process` にしています |
| C speed | `capability.shortestLeadTime` = 標準7日／最短翌日（対になる2値） | **comparison を主役にすることが妥当か。** 規則版は `conditions:comparison` を選んでいます |

**単なる変更は価値ではありません。**
AIが規則版と違う判断をした場合、`project.json` の材料を確認して、
**その情報を主役にする合理的な根拠があるか**を評価者が確かめます。
