### 3. 検証の準備中に見つけた欠陥を直した（D-224・D-225）

**これが今回いちばん重要な発見です。**

ダミーのキーで報告の経路を通したところ、APIが401で落ちて規則版に戻した案件で、
**強みページと設備ページの帯が変わり、しかも `ai` の印が付いていました。**

```
  判断の出所：AI版→規則版に戻した
    strengths/index    **変わった**
        conditions:largeNumber:quiet  →  conditions:spec:lead　[ai]   ← これが出てはいけない
```

`ai-fallback` の中身は**規則版そのもの**です。渡しても渡さなくても同じでなければなりません。

原因は、Brief が「内容ごとに1つの値」を持つのに対し、
**同じ内容でもページによって出し方が違う**ことでした。
強みページの条件の帯は「強みを読んだあとに確かめてもらう」控えめな帯で、
対応可能範囲のページでは主役です。Briefはその区別を持てません。

直し方は2つ入れました。

1. **採用されなかった Brief（`rules` / `ai-fallback`）は構成に効かせない**（D-224）
2. **Brief が効くのはトップページだけにする**（D-225）。
   AIが決めるのは「何を主役にするか」で、それはトップページの話です

いまは401でも**全ページ変化なし**になります。

> **なぜ前回の試験を通り抜けたか。**
> トップページの**表現だけ**を見て、**強さ（emphasis）も下層ページも見ていなかった**からです。
> 試験を「全ページ・強さ込みで1文字も変わらないこと」に直しました。
> 見ていないものは、通ります。

### なぜ C か

**① 精度の証拠を、自分で下げた。**
A社の設備は2行しかありませんが、その1つが **ミツトヨ CRYSTA-Apex（三次元測定機）**です。
A社の強みは精度で、お客様の言葉は「**測定成績書がそのまま使える**」、事例は「他社の成績書が通らなかった」。
**±0.005mm と測定成績書を支えている物証が、この三次元測定機です。**
それをトップページで `quiet`（控えめ）に下げました。**主張は残して、証拠を小さくした**形です。

**② 会社ごとの差が、測って縮みました。**

| | A×B | A×C | B×C | 平均 |
|---|---|---|---|---|
| 規則版 | **0.25** | 0.43 | 0.43 | **0.37** |
| AI版 | **0.43** | 0.43 | 0.43 | 0.43 |

A社の `technique` が `process` になったことで、**B社・C社と同じ組み合わせになりました。**
この事業の設計目的は「同じ型でも会社ごとに違って見えること」（D-209）で、
**AIはその指標を悪い方向に動かしています。**

**③ しかも、A社の `technique` の材料は3社中いちばん薄い。**
`followUpFindings` は A社が【温度管理】の1件のみ。B社・C社は2件ずつです。
「してから」という語があるため材料検査は通りますが（`hasSteps`）、
**工程として見せる材料が最も少ない会社に、工程の見せ方を与えた**ことになります。

**弁護できる点も書いておきます。** 規則版がA社の `technique` に `prose` を選んだのは、
`PLAYBOOK.precision.prefer` に `technique` の項目が無く、**既定へ落ちただけ**です。
規則版はここに意見を持っていません。温度管理（20℃±1℃・30分暖機）を手順として見せる発想自体は、
±0.005mm の裏づけとして筋が通ります。**単体なら B でもよい変更です。**
ただし `equipment` の `quiet` と差の縮小を合わせると、**全体としては規則版より悪い**と判断します。

## 報告しておくべきこと（2点）

### ① 4段検査は、A社の判断を止めませんでした

**当然です。検査が見ているのは「語彙にあるか」「材料があるか」「可否表を通るか」だけで、
「その優先順位が妥当か」は見ていません。**
A社の `equipment:list/quiet` は、語彙にあり・材料があり・可否表を通ります。だから通りました。

**つまり、AIの判断の妥当性を止める仕組みは、いまも人の目しかありません。**
この検証で唯一 C を出した判断が、機械では1つも引っかからなかった。
D-219・D-221・D-222 のときと同じ構図です（数値の検査は全部緑だった）。

### ② `source` が `ai` でも、画面が変わっていないことがある

C社は `source: ai` と出ますが、**最終HTMLは規則版と1バイトも違いません。**
`source` は Brief 全体（帯ごとの `data-decided-by` とは別）の印なので設計どおりですが、
**意思決定の材料としては「画面としては規則版と同じ」と読む必要があります。**
表の8欄だけを見て「3件ともAIが効いた」と読むと、事実を取り違えます。

## 判定と、次にすること

**1/3 ＝「可能性は確認。実案件には投入しない」**

- **実案件（松原精機）の既定は規則版のまま。** `npm run generate -- matsubara-seiki` は今までどおり
- **AI版は消さない。** 作ったまま、既定にしない（D-215の設計どおり、`--ai-brief` を付けたときだけ動く）
- AI OFF の基準（`baseline-ai-off.json`）は一致を維持。`npm test` 265/265

**B社で見えたものが、いちばん重要でした。**
AIが効いたのは「新しい見せ方を思いついたから」ではなく、
**規則版が意見を持っていない場所と、材料が薄いのに主役にしていた場所を、材料から読み直したから**です。
逆にA社で外したのも同じ理由で、**規則版が既定に落ちていた場所**でした。

つまり**当たりも外れも、規則版の手薄なところで起きています。**
`PLAYBOOK` に `technique` の指定が無い（`precision`）、`tolerance` が空でも `lead` にする（`difficulty`）——
**AIを入れるより先に、規則版のこの2箇所を直すほうが、確実で、毎回同じ結果になります。**
