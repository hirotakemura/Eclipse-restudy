## 0. まず、いまの差を数字にしました

`npm run qa:directions` を作りました。**同じ会社のデータから、写真を全部外して、型だけを変えて6通り書き出し、構造がどれだけ違うかを測ります。**

### 結果（改修前の基準値）

| 条件 | まったく同じ構成になった組み合わせ | 平均の似ている度合い |
|---|---|---|
| 型だけを差し替えた場合 | **15通り中 15通り** | **1.00** |
| 型を押して9軸も変わる場合（実際の操作） | **15通り中 7通り** | **0.89** |

```
標準       最初の画面 headline ／色 #10456f
老舗・職人   最初の画面 headline ／色 #8d2f36
食品・環境   最初の画面 headline ／色 #1f6f4a
生活サービス  最初の画面 headline ／色 #94580c
   ↑ この4つは、構成がまったく同じ。**違うのは色だけ。**
```

**ご指摘のとおりでした。** 写真ゼロでは、いまの型は**色を変えているだけ**です。

構造に差が出ているのは「最初の画面」が `spec` か `headline` かだけで、
それが `対応できる条件` の帯と `主な設備` の帯を出し入れしているに過ぎません。

**この 0.89 を下げることが、改修の合格条件**です。

## 2. Design System の語彙（提案）

**語彙を増やすこと自体は目的にしません。** 安全に組み合わせられる有限の集合にします。

各軸に「何が選べるか」と、**それぞれが写真ゼロで効くか**を書きます。

### ① 面（surface）— 帯の地

| 値 | 中身 | 写真ゼロで効くか |
|---|---|---|
| `plain` | 白地 | ○ |
| `soft` | 薄地 | ○ |
| `accent` | アクセント地＋白文字（いまの誘導帯と同じ扱い） | ○ |
| `grid` | 白地＋**方眼**（CSSの線。画像を足さない） | ○ **技術系で効く** |
| `rule` | 白地＋上下の太い罫 | ○ |
| `paper` | 薄地＋**紙のような粒**（CSSのグラデーション） | ○ 老舗系で効く |

**暗い面は作りません**（D-199）。

### ② 組み方（layout）— 帯の中身の並べ方

| 値 | 中身 | 写真ゼロで効くか |
|---|---|---|
| `stack` | 上から順（いまの唯一の形） | ○ |
| `split` | 左右2分割（見出し＋本文／本文＋数字） | ○ |
| `offset` | **非対称**。片側に寄せて余白を大きく取る | ○ |
| `editorial` | 大きな文字＋狭い本文＋広い余白 | ○ |
| `fullbleed` | 画面いっぱい | △ 写真があるほど効く |

### ③ ファーストビュー（hero）— 6つに（ご指示⑫）

| 値 | 中身 | 写真ゼロ |
|---|---|---|
| `headline` | 大きなキャッチ | ○ |
| `spec` | 対応範囲を先に | ○ |
| `figure` | **大きな数字を主役に**（±0.01mm・最短3日） | ○ **いちばん差が出る** |
| `type` | **大きな余白＋強いタイポグラフィ** | ○ |
| `motif` | **技術グラフィック中心**（寸法線・方眼） | ○ |
| `photo` | 写真を大きく | × 写真が要る |

### ④ 情報の大小（scale）

| 値 | どこに使うか |
|---|---|
| `hero-figure` | 最大。`±0.01` のような1つの値だけ |
| `lead` | この会社を一言で言うもの |
| `normal` | 本文 |
| `quiet` | 補助 |

**Company Analysis が「何が最大の強みか」を決め、その1つだけを `hero-figure` にします。**

### ⑤ モチーフ（motif）— 1〜3個（ご指示⑦）

| 値 | 何から選ぶか |
|---|---|
| `dimension` 寸法線 | 公差・精度が聞き取れている会社 |
| `grid` 方眼・座標 | 図面・設計が強みの会社 |
| `process` 工程線 | 工程の工夫が強みの会社 |
| `section` 断面 | 難加工・薄物の会社 |
| `grain` 素材の目 | 材質の幅が強みの会社 |
| `none` | 材料が無ければ**付けない** |

> **歯車アイコンのような「工場っぽいもの」は入れません**（ご指示⑦）。
> **聞き取ったデータから意味のあるものだけ**を選びます。

### ⑥ 写真の扱い（media）

`none` / `inline` / `side` / `full` / `frame` / `mono`
**写真が無ければ `none`。無理に写真中心にしません**（ご指示⑥）。

### ⑦ ナビ（nav）

`standard`（上に横並び）／ `sidebar`（左）／ `minimal`（細く小さく）／ `compact`（ページが多い会社）

### ⑧ 動き（motion）

`none` / `subtle` / `standard` の3段階。**既定は `subtle`。**

**実装原則（ご指示③・そのまま固定します）**

- JSが動かなくても本文は読める
- **初期状態を `opacity: 0` にして本文を隠さない**
- 動きが無くても情報構造が成立する
- `prefers-reduced-motion` に対応する
- 印刷時にも本文が消えない
- 重いアニメーションライブラリを使わない

> 実現方法：`@media (prefers-reduced-motion: no-preference)` の**中だけ**で
> `@starting-style` や `animation-timeline` を使い、**素のHTMLは最初から見えている**状態にします。

### ⑨ スマホでの見せ方（mobile）

**各 `layout` が、スマホでどうなるかを定義に持たせます**（ご指示⑰）。

| layout | スマホ |
|---|---|
| `split` | 縦に積む |
| `offset` | 余白を戻して1カラム |
| `editorial` | 文字サイズを1段落とす |
| `fullbleed` | 左右の余白を戻す |

## 3. 型（Design Direction）の定義（提案）

**型は「6個の固定テンプレート」ではありません。** 語彙の**好み**を持つだけです。

```ts
interface Direction {
  id: string;            // standard / technical / ...
  label: string;         // 標準 / 精密加工 …（日本語）
  note: string;
  tone: Tone;
  favor: ShowBy[];       // 前に出す（いまもある）
  defer: ShowBy[];       // 後ろに回す（いまもある）

  // ここから新設。**いずれも「好み」であって固定ではない**
  surfaces: Surface[];   // 使ってよい面。先頭が既定
  layouts: Layout[];     // 使ってよい組み方
  heroes: Hero[];        // 向いているファーストビュー
  motifs: Motif[];       // 候補。材料が無ければ none
  motion: MotionLevel;
  nav: NavStyle;
}
```

**同じ型でも、会社によって出るものが変わります。**

| 例 | technical（精密加工）を選んだ会社 |
|---|---|
| A社：公差が聞き取れている | hero=`figure`（±0.01を大きく）／motif=`dimension` |
| B社：公差は未確認、断られた案件が強い | hero=`spec`／motif=`section`／`declined` を lead |
| C社：設備の型番が揃っている | hero=`spec`／`equipment` を前に／motif=`grid` |

## 4. 生成の流れ（ご指示④・⑤）

```
project.json
   ↓
Company Analysis          何が材料としてあるか（いまのまま・規則）
   ↓
Content Journey           何を、どの順で見せるか　←★骨格。順序の決定者はここ一つ
   ↓
Design Brief              その中で何を強く見せるか（語彙から選ぶ）
   ↓
Design System             語彙の実体（CSS変数＋data属性）
   ↓
Page / Section Composition
   ↓
Copy
   ↓
Astro
```

**順序の決定者を2つ作りません**（ご指示⑤）。
Journey が骨、Analysis は**その骨の中の強弱**を決めます。

### Design Brief の再生成（ご指示④）

- `npm run generate` は**毎回 project.json から作り直す**
- `npm run generate -- --keep-brief` で固定できる
- Brief に **`sourceProjectHash`** を持たせ、**いまの project.json から作られたものかを検査**できるようにする
- ハッシュが合わなければ、書き出しのときに警告を出す

## 5. 検査（ご指示⑥）

**総当たりで増やしません。** 3段に分けます。

| 段 | 何を見るか | いまの状態 |
|---|---|---|
| **1. 機械検査** | `opacity:0` による本文非表示／文字切れ／はみ出し／`{{要確認}}`／社内語／存在しない画像／リンク切れ／project.json に無い数値・固有名詞 | 3種（事実検証15・社内語18・原稿の指示21）。**`opacity:0`・はみ出し・リンク切れは未実装** |
| **2. Design System 検査** | 語彙の外の色・書体・radius が使われていないか。禁止した組み方が出ていないか | **未実装。** いまのコントラスト検査84件はここに含める |
| **3. Visual QA** | 6つの型が**画面上で明確に違って見えるか**。代表案件に絞る | **`npm run qa:directions` を作った。** 構造の差は機械で測り、見え方は人が見る |

**数が増えるのは1と2で、どちらも機械です。** Visual QA は6通りだけ、人の目で見ます。

### 変えるもの

Astro の静的生成／Cloudflare Pages ／**写真が無くてもサイトが建つこと**

**取材項目は1つも増やしません。**
