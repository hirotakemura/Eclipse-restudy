## 1. 商品構成

**商談で出すのは3つまで。**選択肢が多いと売れない。
①②は製造業向けの本命商品、③は紹介経由の受け皿で、**商談の場に3つ並べない。**

### ① スタンダード制作 — 980,000円（税別）

中小製造業のコーポレートサイト。10〜15ページ想定。

含むもの：
- 取材90分 ×1回（オンライン可）
- **全ページの原稿作成**（技術説明・強み・製品紹介まで）
- 構成設計・デザイン・実装・公開
- 写真の指示書（何をどう撮るか）／簡易撮影は別途
- スマホ対応、基本SEO設定、問い合わせフォーム、Googleビジネスプロフィール設定
- 公開後30日の無償修正

納期：**4週間**（原稿待ちが発生しないため）

### ② ライト制作 — 480,000円（税別）

5ページ以内。既存サイトのリニューアルで、素材が揃っている場合。
下請け案件・紹介案件の受け皿。

### ③ 汎用ベーシック — 198,000円（税別）※2026-09-12 追加

**サイトがない中小・零細企業向け。業種を問わない。** 5ページ以内。

含むもの：
- 聞き取り30分（オンライン可）
- **全ページの原稿作成**（ここは980,000円の商品と同じ。顧客に書かせない）
- デザイン・実装・公開／スマホ対応／問い合わせフォーム
- 公開後14日の無償修正

含まないもの：
- 業界特化の技術ページ（対応材質・精度・設備一覧）。**これは製造業向け商品の中身**
- 深いSEO設計、事例の作り込み、競合調査

> **この商品はこちらから売りに行かない。**
> 紹介・商工会議所・自社サイト経由で「向こうから来た」案件の受け皿（D-045）。
> 単価198,000円で営業をかけると、1受注あたりの営業工数が単価に見合わない（`16-低単価多件数モデルの検討.md`）。
>
> **汎用フォームで製造業の案件を受けないこと。** 技術ページが作れず、商品として成立しない。

### ④ 保守・更新 — 都度対応（2026-09-12 改訂）

**月額の固定費はいただきません。**

```
　更新作業　　1回 15,000円〜（作業量に応じて）／ 時間単価 10,000円
　48時間以内に反映（軽微なもの）。電話での依頼も受ける
```

**無償で続けるもの**（原価が実質ゼロのため・`10-インフラとアフターフォロー方針.md` 第3章）

```
　死活監視 ／ フォーム疎通の週次テスト ／ ドメイン・SSL期限の管理 ／ 月次レポートの自動送付
```

> **無償で出す理由は善意ではなく営業です。**
> 毎月レポートが届く＝**顧客との接点が切れない。** 接点があれば、更新依頼も追加案件も紹介も出てくる。
> **原価ゼロの接点維持装置**として使います（D-045）。
>
> 更新依頼のハードルを下げることが、最大の解約防止策でもあります。
> **「頼みづらくて放置」が、サイトが死ぬ典型的なパターン**だからです。

**保守・更新の実務はアドバイザーが担当します**（D-055）。

## 2. 値付けの根拠（値引き要求への回答を先に用意しておく）

- 98万は中小製造業にとって「稟議を通せる上限に近い額」。100万を超えると決裁の階層が上がる会社が多い。**あえて98万に置く。**
- 補助金（持続化補助金・上限200万／補助率2/3）を使えば自己負担は約33万。**この数字を提案書に必ず書く。**
- 値引きは受けない。代わりに**スコープを削る**（ページ数を減らす、ライト制作に落とす）。一度値引きすると運用費も削られ、その顧客は永久に不採算になる。

## 3. 制作フロー（4週間）

| 週 | 内容 | 顧客の作業時間 |
|---|---|---|
| Week 0 | 契約・キックオフ・競合調査 | 30分 |
| Week 1 | **取材90分** → 構成案・原稿ドラフト提出 | 90分 |
| Week 2 | 原稿確定・デザイン提出 | 60分（確認のみ） |
| Week 3 | 実装・写真手配 | 30分 |
| Week 4 | 検収・公開・運用説明・**引き渡しパッケージの受け渡し** | 60分 |

**顧客の総作業時間 約4.5時間。** これを提案書の一番目立つところに書く。競合は「お客様に原稿をご用意いただきます」と書いている。ここが勝負所。

## 4. 技術スタック（社長決定 / 2026-09-12 改訂）

> **WordPress採用を撤回した。** 理由は `10-インフラとアフターフォロー方針.md` 第1章に詳述。
> 要点：保守工数がサイト数に比例して増え、週15時間の体制では保守契約の粗利が成長とともに下がる構造になるため。

| 用途 | 採用 | 理由 |
|---|---|---|
| コーポレートサイト | **Astro（静的サイト生成）** | 保守工数がほぼゼロ。表示速度で競合と明確に差がつく |
| ホスティング | **Cloudflare Pages** | 無料枠で足りる。障害がほぼ起きない |
| フォーム | Pages Functions + Resend + Turnstile | 原価ゼロ。テンプレート化できる |
| ドメイン | **顧客名義で取得** | 乗り換え自由の担保。更新切れの責任も負わない |
| デザイン | Figma | |
| 制作基盤 | **自社ツール KOBO** | `11-自社ツール設計_KOBO.md` |

顧客がWordPressを指定してきた場合は対応するが、**運用契約に月額2万円を上乗せする**（保守工数が実際に増えるため）。

### コンテンツ更新の考え方（当初方針からの変更）

WordPressを選んだ当初の論拠は「顧客が自分で更新できる」だったが、これは実態に合わない。
中小製造業にWordPressを渡して更新を続ける会社は1割に満たない。使われない機能に保守コストを払い続けることになる。

→ **更新は保守契約に含めて我々が代行する（ベーシックで月2回まで）。**
顧客にとってもラクで、我々にとっては保守契約の価値の裏付けになる。

### 自社制作基盤への投資（最重要）

2件目以降の原価を下げられるかどうかで、この事業の利益率が決まる。
これを実装したものが自社ツール **KOBO**（`11-自社ツール設計_KOBO.md`）。

- ヒアリング入力 → 原稿生成 → Astroテンプレートへ流し込み → Cloudflare Pages へ公開
- 製造業向け共通テンプレート（対応可能範囲・設備一覧・加工事例を標準実装）
- 取材台本（`06`）がそのままフォームの仕様になる

**目標：3件目以降、制作の実工数を初回比50%以下にする。**
週15時間の制約下では、削減した制作工数がそのまま営業に使える時間になる。

## 5. やらないこと

- ECサイト構築（工数が読めず、運用負荷が高い）
- 大規模Webシステム開発（体制が持たない）
- デザインコンペ・相見積もり案件への参加（勝率が低く工数が消える）
- 「安くやります」提案（一度やると戻れない）
