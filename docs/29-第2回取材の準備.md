# 第2回取材の準備 — 工場・60分

作成 2026-09-14　／　対象：有限会社 松原精機（第1回はモック取材）

---

## この文書の立ち位置

台本そのものは `06-取材台本.md` にあります。**ここはその続きで、「第2回をどう準備するか」だけ**を書いています。

第1回との違いは3つです。

| | 第1回 | 第2回 |
|---|---|---|
| 相手 | 社長 | **工場長・現場の方** |
| 場所 | 会議室 | **工場** |
| 目的 | 引き合いの実態・強み・事例の輪郭 | **技術の裏取りと、数字の確定** |

**第2回は「聞く」より「確かめる」取材です。** 社長が口頭で言った型番を銘板と照合し、
「うろ覚え」と言われた工程を、実際にやっている人から聞き直します。

## 宿題リストは、手で作りません

```
cd tool
npm run gaps -- matsubara-seiki --write
```

`project.json` から、埋まっていない欄を全部拾って、印刷できる形で出します。

**手で写した宿題リストは、必ず古くなります。** 写し間違えるか、データを直したときに片方だけ古くなる。
データから出せば、取材の直前に走らせるだけで、そのときの正しい状態が出ます。

出てくるものは、**埋まらないと何が起きるか**の順に並びます。欄の順番ではありません。

```
■ 埋めないと、ページが作られない／中身が欠けたまま出ます　8件
■ 裏を取ってください（間違っていると事故になります）　　　3件
■ 埋めると、ページの中身が増えます　　　　　　　　　　　25件
```

そして**誰に聞くかで2つに割れます。**

```
現場で聞くこと　36件　←　工場でしか確かめられないもの
メールで足りること 26件　←　資本金・電話の受付時間・会社名のかな　等
```

> **資本金を、機械の前に立って聞かないでください。**
> 全部を1枚に並べると、現場でしか聞けないことが埋もれます。
> 事務のぶんは、取材の前に社長へメールで送ります。

## 60分の配分

```
　 0–05　ごあいさつ・目的の共有（「今日は確かめに来ました」）
　05–25　■ 埋めないと、ページが作られない　8件　　★ここが本体
　25–40　■ 裏を取る　3件（銘板を見ながら歩く）
　40–50　写真
　50–60　■ 中身が増えるもの（時間の許すかぎり）・次の段取り
```

**最初の20分に、止まっているものを全部当てます。** 工場を歩き始めると止まらないので、
歩く前に座って聞くほうが確実です。歩くのは「裏を取る」ところから。

## 今回いちばん取りに行くもの

第1回で埋まらず、**いま現に原稿が作れていない**のがここです。

### ① 事例2・事例3の「どう解決したか」

```
いま：{{要確認}} 具体的な工程の工夫を工場長に確認する（社長はうろ覚え）
```

この2件は、**原稿ページそのものが作られていません**（D-254）。
材料が無いものをAIに書かせると `{{要確認}}` だらけの原稿が出てきて、費用だけかかるためです。

聞き方は、社長の言葉をそのまま渡すところから始めます。

```
　「社長からは『他社が歪みで断った案件を受けた』とうかがっています。
　　あれ、現場ではどうやって通したんですか」
```

> **「工夫はありますか」と聞かないでください。** ほぼ「特にないですね」と返ってきます。
> 第1回で最大の強みだった「治具の内製」も、定型質問では一度も出ず、
> **「薄物は歪む」を受けた追い質問でだけ出ました**（`15-第1回モック取材_検証結果.md` 第4章）。

### ② 対応精度・対応サイズ（最大・最小）

```
いま：取材で答えが出なかった（「ミクロン単位までは可能です」）
```

**この答えは、そのままでは使えません。**「ミクロン単位」は無内容で、検索にも一件も拾われません。
かといって「±5μm」と埋めるのは捏造で、いちばん危険です。

現場では、**図面か測定成績書を見ながら**聞きます。

```
　「直近で出された成績書、1枚見せていただけますか。
　　このくらいの公差なら通る、という線はどのあたりですか」
```

### ③ 加工法・工法

対応可能範囲のページの中心です。**材質 × 加工法**で検索されるので、ここが埋まらないと検索に出ません。

### ④ 事例1の「結果」

事例ページは作られますが、**「結果」の節が丸ごと消えたまま公開されます。**
調達担当者が見ているのは結果です（D-172）。

## 写真

**写真の方針（実写か、図版か）は、まだ決まっていません**（ご友人と相談中）。
ただし、**方針が決まってから撮りに行くのでは遅い**です。撮り直しのための再訪はいちばん高くつきます。

今回は「**撮れるものは撮っておく**」で進めます。置き場所は `06-取材台本.md` の表のとおり。
優先はこの順です。

```
　最高　加工事例の現物　　1〜3枚／件　←　いちばん問い合わせに繋がる
　高　　工場・設備　　　　3〜8枚（銘板の写真と兼ねられます）
　高　　外観　　　　　　　1枚
　高　　代表者　　　　　　1枚（第2回は社長が不在の可能性あり。後日でよい）
```

> **その場で「これを載せてよいか」を確認してください。**
> 工場の写真には、社外に出せない設備や、他社の図面が写り込みます。

## 事前に送るもの（取材の3日前まで）

### 1. 社長へ — メールで足りること 26件

`npm run gaps` の後半をそのまま送ります。会社名のかな・資本金・電話の受付時間など、
**工場で聞く必要のないもの**です。

### 2. 工場長へ — 考えておいていただくこと

回答は不要です。当日その場で思い出せるように、という趣旨です。

```
　・他社様が断った案件を受けたとき、現場で何を変えたか（治具・段取り・順序）
　・直近の測定成績書を1枚、見せていただけますか
　・設備の銘板が見える状態にしておいていただけますか
```

### 3. こちらの持ち物

`06-取材台本.md`「持ち物」に加えて、今回は次を足します。

```
　・npm run gaps -- matsubara-seiki --write で出した紙（印刷）
　・第1回で書き出したサイト（画面で見せられる状態）
```

> **第1回のサイトを見せると、話が早くなります。**
> 「ここが空欄なのは、これを聞けていないからです」と画面で指させます。
> 口で説明するより、埋める意味が伝わります。

## 取材のあと

```
cd tool
npm run gaps -- matsubara-seiki    # 埋まったか、もう一度確かめる
npm run build:site -- matsubara-seiki
```

**原稿の生成は、ここまで済んでから1回でまとめます。**
第1回の原稿はすでに手元にありますが、材料が変われば書き直しになるので、
**埋まる前に生成すると、同じ費用を2回払うことになります**（アドバイザーのご判断）。

埋めた欄は、**聞いた言葉のまま**入れてください。整えるのは後の工程です（D-013）。
