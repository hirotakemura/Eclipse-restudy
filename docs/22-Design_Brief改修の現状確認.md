## 0. 測った結果

ご指摘「配色・書体・レイアウトを変更しても、白背景＋見出し＋本文＋カード＋表に戻る」を、数字で確かめました。

| 測ったもの | 結果 |
|---|---|
| トップページの帯7つのうち、**背景があるもの** | **2つだけ**（下部の緑の誘導帯と、脚） |
| 本文の帯5つの背景 | **すべて `rgba(0,0,0,0)`＝白** |
| 6配色すべての `bg` | `#ffffff` / `#fffdfc` / `#fffdfa` … **全部ほぼ白。暗い背景の選択肢は存在しない** |
| 章を交互に塗る選択肢（`sections: alternate`）の濃さ | **白 対 薄地 = 1.08〜1.10:1。実測でほぼ見分けがつかない**（D-192） |
| `animation` / `@keyframes` / `transition` | **0件** |
| `prefers-reduced-motion` | **0件** |
| 画像の加工（filter / clip-path / mask） | **0件**。`aspect-ratio` と `object-fit` のみ |
| グラフィック・モチーフ | **0件** |
| ヘッダーの型 | **1つ**（`nav` は「上／左」の置き場所だけで、見た目は同じ） |
| ファーストビューの型 | 3つ（見出し先／写真大／対応範囲先） |

**ご指摘のとおりです。** 背景表現・モーション・モチーフ・写真加工は、**選択肢がそもそも存在しません。**

## 3. Design Brief をどこに追加するか

**`tool/lib/design/brief.ts`（新設）**、`analysis.ts` と `sections.ts` の**あいだ**です。

```
analyze()      … 何が材料としてあるか（事実。いまのまま）
   ↓
brief()        ← ここを新設。見せ方の方針を決める
   ↓
composeX()     … セクションの配列（brief を受け取る形に変える）
```

保存先は **`project.json` の `designBrief`**（最上位・`theme` の隣）。理由：

- **取材データではないので、取材項目に混ぜない**（ご指示 §25「取材項目を大量追加しない」）
- 保存すれば、**同じ案件を2回書き出しても同じサイトになる**（再現性）
- 社長・お客様が**あとから中身を読んで直せる**

### 生成AIをどこで使うか

**brief() の中だけ**です。ただし**自由記述にしません。**

> **AIが選べるのは、Design System が列挙した語彙の中からだけ**にします（ご指示 §21 と同じ）。
> 「背景 = `dark` / `grid` / `paper` / `plain` のどれか」という形にして、
> **値そのものを作らせない。**
>
> 理由は D-181 と同じです。値を作らせた瞬間、`verify.ts` の効かない捏造経路が増えます。
> 語彙を enum にしておけば、**AIが何を返しても機械で検査できます。**

**費用**：前回お答えしたとおり、1案件につき1回の呼び出しなので**増分は「1ページ分」程度**です。
ただし**人が Brief を確認してから原稿を書く運用にすると、キャッシュ（保持5分）が切れて費用が上がります。**

## 4. Design System をどこに追加するか

**`tool/lib/theme.ts` を分割**します。いま338行で、配色・書体・雰囲気・9軸が全部入っています。

```
lib/design/system/
  palette.ts     配色（既存の6つ＋暗色面の定義を追加）
  type.ts        書体・文字サイズ・見出しの階層
  space.ts       余白・幅・リズム
  surface.ts     ★新設 背景表現（白／薄／暗／アクセント／グリッド／地紋／画像）
  media.ts       ★新設 写真の扱い（切り抜き・全幅・枠・単色・覆い）
  motif.ts       ★新設 グラフィック・モチーフ（寸法線・図面グリッド・座標）
  motion.ts      ★新設 モーション（none / subtle / standard）
  layout.ts      ★新設 組み方（split / editorial / fullbleed / stack）
```

**`lib/theme.ts` は残します**（既存の import を壊さないため、再輸出だけにする）。

### ここで必ず守ること

| 守るもの | なぜ |
|---|---|
| **暗い背景を足すなら、コントラスト検査も倍にする** | いまの84件は**すべて明るい背景の前提**。暗色面を足した瞬間、検査の外側が生まれる（D-191） |
| **地紋・グリッドは CSS で描く。画像を足さない** | 静的サイトの表示速度を落とさない（ご指示 §18） |
| **モーションは `prefers-reduced-motion` で必ず止める** | ご指示 §11 |
| **散文の1行は 40em 前後に保つ** | 幅や組み方を変えても、ここは動かさない（D-154） |

## 5. ページ構成生成をどこに追加するか

**すでにある `lib/design/sections.ts` を拡張**します。新設ではありません。

いまの `Section` は `{ kind, width, emphasis, heading }` の4つ。ここに足します。

```ts
interface Section {
  kind; width; emphasis; heading;      // いまある
  surface;   // 背景（plain / soft / dark / accent / grid / paper）
  layout;    // 組み方（stack / split / editorial / fullbleed）
  media;     // 写真の扱い（none / inline / side / full / collage）
  motion;    // 動き（none / fade / count-up / draw / reveal）
  motif?;    // モチーフを敷くか
}
```

Astro 側は `Band.astro` が `data-surface` `data-layout` を受けて描く形に広げます。
**セクションのコンポーネント（Figures / Declined / Points …）はそのまま使えます。**

## 7. ご判断いただきたいこと

実装に入る前に、4点あります。

### ① 「型」の名前と数

ご指示では **TECHNICAL / INDUSTRIAL / CRAFT / ENGINEERING / PRODUCT / BRAND** と書かれています。
いまの6つは **標準／精密加工／老舗・職人／食品・環境／生活サービス／設計・技術**（D-189で日本語に決定）。

| ご指示 | 近いもの | 備考 |
|---|---|---|
| TECHNICAL | 精密加工 | ほぼ同じ |
| ENGINEERING | 設計・技術 | ほぼ同じ |
| CRAFT | 老舗・職人 | ほぼ同じ |
| INDUSTRIAL | — | **無い**（設備・量産が強みの会社） |
| PRODUCT | — | **無い**（製品開発型） |
| BRAND | — | **無い** |
| — | 食品・環境／生活サービス | **ご指示の6つには無い**（うちの商圏では要る） |

**日本語の名前は維持**（取材の場で社長が押すボタンなので・D-189）。
問題は**中身の切り方**です。「INDUSTRIAL・PRODUCT を足して8つにする」のか、
「食品・環境／生活サービスを畳んで6つに収める」のか、ご判断をいただきたい。

### ② 生成AIをどこまで決めさせるか

ご指示 §21 は19項目をAIに決めさせる内容です。D-181 では
「段階1では規則で判定する。**規則では捉えきれない例が3件出たら**生成AIを入れる」と決めました。

**その3件は、まだ1件も出ていません**（実案件が0件のため）。

私の考えは **「語彙はこちらが決め、その中からAIが選ぶ」** です。
自由記述にしなければ、費用も検査可能性も保てます。
ただし **§21 をそのまま実装すると、規則で足りるところまでAIに投げる**ことになります。

### ③ 暗い背景を入れるか

入れると**コントラスト検査が実質2倍**になり、6配色すべてに暗色面の定義が要ります。
効果は大きい（ご指示 §2 INDUSTRIAL）ですが、**いちばん手数がかかる項目**です。

### ④ 順番

私の推奨は **schema.ts の型を直す → Design System の語彙を作る → Brief（規則版）→ Brief（AI版）** です。

**Brief をAIにするのは最後**にしたい。理由は、語彙が固まる前にAIを入れると、
**AIが何を返せるのかが決まっていない**まま作ることになるためです。
