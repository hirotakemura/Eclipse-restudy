# 移管の手順書（DNSの切り替え）

作成: 2026-09-13 ／ 実務担当: アドバイザー（D-055）

> **前提：この作業に詳しくなくても、手順どおりにやれば終わります。**
> 大事なのは覚えることではなく、**事故ったときに戻せる状態で始めること**です。

---

## 0. 覚える言葉は3つだけ

| 言葉 | たとえると | 誰が持っているか |
|---|---|---|
| **ドメイン** | 住所そのもの（`matsubara-seiki.co.jp`） | **お客様名義**（D-011・D-105） |
| **ネームサーバー** | 「この住所のことは、あの案内所に聞いてください」という指定 | レジストラの画面で、**お客様が変えられる** |
| **DNSレコード** | 案内所が持っている案内の中身（サイトはここ、メールはここ） | その案内所（我々の場合はCloudflare） |

**移管＝「案内所を引っ越す」ことです。** 住所（ドメイン）は動きません。

---

## 1. いちばん大事なこと

> ### ★ MXレコード（メールの受け先）を先に控える
>
> 案内所を引っ越すとき、**サイトの案内だけ持って行ってメールの案内を忘れると、会社のメールが止まります。**
> サイトが数時間見えないことより、はるかに重大な事故です。
> お客様には「**ホームページを作り直したらメールが来なくなった**」と映ります。

```
npm run dns -- matsubara-seiki.co.jp matsubara-seiki
```

今の設定が全部出て、案件フォルダに控えが残ります。**この控えを取る前に、何も触らないこと。**

```
  ★ MX（メールの受け先）
      10 mx01.example-mail.jp

  ★ このドメインでメールを使っています。
     切り替え先にも同じMXを必ず設定してください。**忘れると会社のメールが止まります。**
```

---

## 2. 【引き取る】既存のドメインで新しいサイトを公開する

実務でいちばん多いのがこれです。**作業そのものは30分ほどですが、切り替えは平日の午前にやります。**

```
　① 控えを取る　　　　  npm run dns -- <ドメイン> <案件ID>
　　　　↓
　② お客様に口頭で確認  「このドメインでメールもお使いですか」
　　　　↓
　③ TTLを下げる　　　　 現在の案内所で、TTLを300秒にする（1週間前にやる）
　　　　　　　　　　　　 **戻すときの反映が速くなる。保険です**
　　　　↓
　④ Cloudflareに追加　  ドメインを追加すると、今の設定を自動で読み込む
　　　　↓
　⑤ **目視で照合**　　　①の控えと見比べる。**とくにMXが全部入っているか**
　　　　↓
　⑥ サイトの向き先　　　新しいサイト（Pages）に向ける
　　　　↓
　⑦ ネームサーバー変更  **レジストラの画面で、お客様に操作していただく**
　　　　　　　　　　　　 （ここで初めて切り替わる。ここまでは何も起きない）
　　　　↓
　⑧ 反映を待つ　　　　  数分〜最大48時間。TTLを下げてあれば数分
　　　　↓
　⑨ 確認　　　　　　　  npm run dns -- <ドメイン>　でもう一度見る
　　　　　　　　　　　　 **お客様にメールの送受信を1往復テストしてもらう**
```

> **⑦より前は、いつでもやめられます。** 実際に切り替わるのは⑦だけです。
> ⑥までを先に全部済ませておいて、⑦を最後にまとめてやる。これが事故らない順番です。

### やらないこと

| | |
|---|---|
| **控えを取らずに始める** | 戻せない作業になります |
| **金曜の夕方・連休前にやる** | 事故ったとき、対応できない時間が長くなります |
| **MXを確認せずにネームサーバーを変える** | 会社のメールが止まります |
| **お客様のレジストラのIDとパスワードを預かって保管する** | 名義はお客様です。その場で画面共有して、操作はご本人にしていただきます |

## 3. 【出ていく】他社へ引き継ぐ

**この作業の主導権は、我々ではなくお客様にあります。** レジストラがお客様名義だからです。

```
　① 引き渡しパッケージを再送　　 サイトの静的ファイル一式・原稿・画像
　　　　　　　　　　　　　　　　　**DNSレコードの全件と、戻し手順**（`17` 第5章）
　　　　↓
　② 次の業者が置き場所を用意　　 我々は関与しません
　　　　↓
　③ 次の業者がレコードを再現　　 ①の控えを渡してあるので、そのまま作れます
　　　　↓
　④ ネームサーバー変更　　　　　 **お客様がレジストラの画面で変更**
　　　　　　　　　　　　　　　　　我々の同意も操作も要りません
　　　　↓
　⑤ 我々の側を片付ける　　　　　 Cloudflareからゾーン削除、GA4・Search Consoleの権限を外す
　　　　　　　　　　　　　　　　　（データはお客様名義なので残ります）
```

**無償での協力は合計3時間まで**（D-120）。超えた分は時間単価10,000円の都度対応です。
違約金は取りません。**最後に一度だけ、理由を聞きます。**

### 3-2. よくある移管先：一般的なレンタルサーバー（エックスサーバーなど）

**移せます。** 渡すのが**静的ファイル一式**だからです（D-119）。
Astroプロジェクトを渡していたら、受け取った業者はビルド環境を用意しないと1文字も直せません。

```
　① お客様がレンタルサーバーを契約　エックスサーバー スタンダードで月額990円〜（2026年9月時点）
　② ファイルをアップロード　　　　　ファイルマネージャかFTP。特別な作業はありません
　③ ドメインを設定し、無料SSLをON　 Let's Encrypt に対応しています
　④ ネームサーバーを変更　　　　　　第2章と同じ手順。**MXの控えを忘れない**
　⑤ 我々の側を片付ける　　　　　　　Cloudflareからゾーン削除、権限を外す
```

#### ★ フォームの送信部分だけは作り直しが必要

**これは必ず先に伝えます。**

我々のフォームは Cloudflare Pages Functions と Resend で動いています。
一般的なレンタルサーバーに移すと、**フォームのページは表示されますが、送信が飛びません。**
PHPで作り直すか、フォームのサービスを使うことになります。

> **ここで効くのが「全ページに電話番号とメールアドレスを載せる」方針です**（D-060）。
> フォームが止まっても、問い合わせがゼロになりません。
> **撤退耐性のために決めたことが、そのまま移管耐性になっています。**

引き渡しパッケージの⑥には、**フォームが受け取っている項目と、通知先メールアドレス**を書いておきます。
次の業者は、それを見れば同じものを作れます。

#### 費用は増えます。そこは正直に伝える

| | 弊社の構成 | レンタルサーバーに移した場合 |
|---|---|---|
| ホスティング | **0円** | 月990円〜（年11,880円〜） |
| SSL | 0円 | 0円（無料SSL対応） |

**「移せますか」への正確な答えは、「移せます。ただし今は無料の部分に費用が発生します」です。**

## 4. 事故ったときに戻す

**戻し方は1つだけです。ネームサーバーを元に戻す。**

```
　レジストラの画面で、ネームサーバーを①の控えの値に戻す
　　　→ TTLを下げてあれば数分で戻る
　　　→ 下げていなければ最大48時間かかる（だから③をやる）
```

**サイトが見えないだけなら急がなくて構いません。メールが止まっていたら、すぐ戻します。**
直してから切り替え直せばいいだけです。

## 5. 「疎い」への対処

### ① Day 90 までに、自社ドメインで1回やる

**練習してから本番に臨みます。** 自社サイトを公開するときが、そのまま練習になります。
一度通せば、手順書の意味が全部わかります。

### ② 最初の1件は、2人でやる

友人と画面を見ながら進めます。**⑦（ネームサーバー変更）の瞬間だけ2人いれば十分です。**

### ③ 新規ドメインの案件では、この作業は発生しない

サイトを持っていない会社（汎用ベーシックの主な対象）は、**新しくドメインを取るだけ**です。
引き継ぐものが無いので、MXの事故も起きません。**最初の数件はここから受けるのが安全です。**
