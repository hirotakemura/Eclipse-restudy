## B. なぜテンプレートに見えるか（構造として）

松原精機のトップページと強みページを、帯ごとに測った。

```
トップ    最大字 44 → 20 → 28 → 20 → 20    余白 141 → 88 → 88 → 106 → 88
強み      最大字 44 → 28 → 20 → 20         余白 141 → 88 → 88 → 53
中身の幅  760 / 1070 の2種類だけ
```

### B-1 見出しと本文の差が弱い（最大の原因）

帯の見出しは **20px または 28px**、本文は **17px**。比は **1.18〜1.65倍**。
山だけが 44px（2.59倍）ある。

つまり階層は**「山」と「平地」の2段**しかない。
`TYPE_ROLES` には11の役割があるのに、**画面に出ているのは実質3つ**である。

とくに `split`（一覧の既定の組み方）は、見出しを **19〜24px に固定**している。
これは D-239 の判断（狭い左列で大きな見出しは語の途中で折れる）で**正しい**。
しかし結果として、**一覧の帯はすべて 20px の見出しになる。**

### B-2 山のあとが平坦

`44 → 20 → 28 → 20 → 20`。
山が上から1/3にあり、**そのあとページは減衰するだけ**で、終盤に何の山もない。
最後の帯（設備の表）と、その前の帯（材質の札）と、その前（事例）が、**同じ視覚的重さ**で並ぶ。

### B-3 余白の差が小さい

密度の倍率は `tight 0.6 / normal 1.0 / loose 1.2 / vast 1.6`。
実寸で **53 / 88 / 106 / 141**。
`normal` と `loose` の差は **18px** で、**画面では差として読めない。**
しかも5帯のうち3帯が同じ 88px である。

### B-4 横の変化が無い

中身が使う幅は **760 と 1070 の2種類**。
見出しの左端は **230 か 385 の2箇所**だけ。
**目が上下にしか動かない。** 余白は「構成した余白」ではなく「余った場所」になっている。

### B-5 面が2種類

`plain` と `rule`（または `soft`）の2つ。
章の区切りは罫線1本。**背景の切り替わりで場面が変わる感じが無い。**

### B-6 「カードが並んでいるだけ」の正体

実際にはカードは少ない（トップページに格子は0）。
問題は**カードの数ではなく、帯の形がすべて同じ**ことである。

```
見出し（20px）→ 中身（17px）→ 余白88px →
見出し（20px）→ 中身（17px）→ 余白88px → …
```

**同じ部品が同じ間隔で積まれている。** これがテンプレートに見える正体である。

### B-7 写真0枚のとき、仮画像が一番大きい視覚物になる

実測：トップページで最も大きい面積を占めるのは **1030×500 の灰色の仮画像**で、
そこに「仮の画像（外観）／差し替え前提」と書いてある。
**写真が無い会社ほど、画面の主役が「無い写真」になる。**

## C. 15方向それぞれの視覚原則（1〜3個ずつ）

**いまの実装（面・組み方・地紋・気分）から導いたもの**で、新しい語彙は増やしていない。

### 製造業

| 型 | 視覚原則 |
|---|---|
| **standard** 標準 | ①一本道の読み順（`stack` 中心）②罫線で章を切る ③**差をつけない**——迷ったときの安全な既定 |
| **technical** 精密加工 | ①**値が見出しより大きい**（数値の階層）②方眼・寸法線の規律＝要素を格子に乗せる ③行間を詰める（`katai`） |
| **craft** 老舗・職人 | ①**紙の地と読み物の余白**（`paper` + `editorial`）②**非対称**（`offset`）③人の言葉を大きく |
| **engineering** 設計・技術 | ①**正確な整列**（`split` の左見出しを軸線として使う）②工程・断面の注記 ③図と本文が同格 |
| **industrial** 量産・設備 | ①**暗い面で締める**（`dark`）②**全幅で数と体制を見せる**（`fullbleed`）③章が交互に切り替わる |
| **product** 製品・開発 | ①**製品を全幅で主役にする** ②やわらかい余白（`yawaraka`）③見出しは下線で軽く |

### 汎用

| 型 | 視覚原則 |
|---|---|
| **seikatsu** 生活サービス | ①やわらかい面が交互に来る ②人が前に出る ③一本道 |
| **shop** 店舗・サービス | ①**アクセント面で価格を強調** ②表を主役に |
| **gstandard** 標準 | ①**何もしない。** 最小構成であることが原則 |
| **editorial** 読み物 | ①**狭い本文・広い余白** ②見出しを大きく ③非対称 |
| **luxury** 静か・上質 | ①**要素を減らす** ②**余白そのものが主役**（帯の間を最大に）③装飾を置かない |
| **modern** モダン | ①**格子**（`grid` 地紋＋`split`）②大きな文字 ③ミニマル |
| **human** 人・温度 | ①**写真を全幅で主役に** ②やわらかい面 ③文字大きめ |
| **dynamic** 力強い | ①**暗い面と大きな文字で締める** ②全幅 ③見出しを帯に |
| **classic** 落ち着き・信頼 | ①**紙の地** ②控えめな装飾と上品な余白 ③文字大きめ |

**共通して言えること**：15方向のうち **9方向の原則が「余白の取り方」か「文字の大きさ」**で表せる。
つまり第7段階で足すべきなのは**装飾ではなく、余白と文字の段**である。

## E. 原則（数値を決める前に）

1. **階層は「山」ではなく「段」で作る。**
   いま 山→平地 の2段しかない。**eyebrow / 見出し / 導入 / 本文 / 注記**の段を実際に画面へ出す。
2. **ページは山のあとにも段を持つ。**
   終盤に**もう1つだけ**小さな山（値か一言）を許す。トップだけ豪華にしない。
3. **余白は比で設計する。** 絶対値は型（`mood`）が決め、**比は共通**。
   いまの 0.6:1:1.2:1.6 は差が小さすぎる。
4. **横の段を増やす。** 幅が2種類では構図が作れない。
5. **型ごとの違いは「段の強さ」2つだけにする。**
   新しい軸を増やさず、**文字の強さ**と**余白の強さ**の2パラメータで表す。
6. **スマホを先に決める。** いま PC より階層が浅い。
7. **写真が無いときの主役を、仮画像にしない。**

# 実装記録（第7段階・1/2/3/7 のみ）

アドバイザーの判断で **1・2・3・7 の4点だけ**を1つの実装単位として入れた。
**4（幅の段）・5（2つ目の山）・6（型に段の強さ）は保留。**

## 1. 余白の比を広げた

```
前 0.6 : 1.0 : 1.2 : 1.6   （最大÷最小 2.7倍）
後 0.5 : 1.0 : 1.5 : 2.2   （同 4.4倍）
スマホ 0.7:1:1.15:1.4 → 0.6:1:1.3:1.7
```

**余白を増やしたのではない。差を広げた。** `normal` は動かしていないので、
大半の帯の見え方は変わらない——変わるのは「続けて読ませる帯」と「山の前後」だけである。

### ここで1つ、書き写した表に引っかかった

倍率は `density.ts` と `site.css` の**2箇所**に書いてあった（`calc(var(--section) * 1.6)`）。
`density.ts` だけを直したとき、**画面の余白は1pxも変わらなかった。**
突き合わせの試験（`visual.test.mjs`）は前からあり、CSSを直すまで赤いままだった。
**D-197 の3度目**である。

## 2. 見出しと導入の段を、実際の画面に出した

| 役割 | 前 | 後 | 1280pxでの実寸 |
|---|---|---|---|
| `sectionTitle` | min21 / 2.2vw / max34 | min22 / **2.6vw** / max38 | 28 → **33px** |
| `lead` | min18 / 1.4vw / max22 | min18 / **1.7vw** / max25 | 18 → **24px** |

**導入の色を戻した。** 実測で、導入は 19px・`--ink-soft`（**6.0:1**）で、
**ページで最も重要度の高い文のひとつが、いちばん薄い文字**だった。
薄さは「控えめ」ではなく「読みにくい」として届く。

**薄い文字を一律に濃くしたのではない。重要度の順に並べ直した。**

| | 色 |
|---|---|
| 見出し・導入・本文・沿革の出来事 | `--ink` |
| 項目名・注記・説明・年・メーカー名・キッカー | `--ink-soft`（据え置き） |

`--ink-soft` を使う箇所は**17箇所のうち2箇所だけ**動かした（`.lead` と `.timeline dd`）。

## 3. 横置きの見出しを「項目名」として組み直した

一覧の帯は既定で `split` になるため、**見出しが軒並み 20px**（本文の1.18倍）だった。

**大きくして直す道は取らなかった。** 狭い左列で大きな見出しは
「対応できる条／件」のように語の途中で折れる（D-239。この判断は変えない）。

直したのは**役割**である。1.18倍の見出しは「小さい見出し」に見えるが、
**字間を空けた項目名にすると、そういうものとして読める。**
語彙は増やしていない——`label`（項目名）は前からある役割である。

### ここでも画面を見て直した

最初は `--t-label`（12px）＋`--ink-soft`（6.16:1）にした。**画面で見たら弱すぎた。**
中身との間が **318px** 空いているので、薄い12pxは見出しではなく「余りもの」に見えた。
**小さくするのはよいが、薄くするのは別の話だった。**
`--t-caption`（14px）＋`--ink`（15.92:1）に直した。

## 7. 最初の画面に仮画像を置かない

**実測：写真0枚の会社のトップページで、画面で最も大きい視覚物が
1030×580 の灰色の仮画像**で、そこに「差し替え前提」と書いてあった。
**写真が無い会社ほど、ページの主役が「無い写真」になっていた。**

仮の画像そのものは消していない（D-242）。**消したのは最初の画面に置くことだけ**で、
写真の帯にはこれまでどおり出る。判定は `analysis.hasRealPhotos` と同じ規則（D-174）。

**空白にはならない。** 最初の画面は 会社名 → 導入（24px）→ 条件の4枡 で、
2で導入が一段上がったぶん、**仮画像が無くても頭が締まる。**
新しい `AssetSubject` も `Presentation` も足していない。
