## 3. サイト数に応じた費用

### 結論：50サイトまで 0円。100サイトでも月5,000円程度

| リソース | 無料枠 | 何サイトまで持つか |
|---|---|---|
| Cloudflare Pages ビルド数 | 500回/月 | 月2回更新なら**250サイト** |
| Pages Functions リクエスト | 10万/日 | **実質無制限**（フォーム送信のみ。静的ページの配信は無制限） |
| Pages ファイル数 | 20,000/サイト | 無関係（1サイト数百ファイル） |
| Resend 送信数 | 3,000通/月 | 1サイト月20件の問い合わせなら**150サイト** |
| UptimeRobot 監視 | 50モニター | **50サイト** ←最初に当たる上限 |
| ドメイン | — | **顧客名義・顧客負担**（D-011） |

**最初に当たるのは死活監視の50サイト。** そこを超えたら有料プラン（月$7程度）。
Resendも150サイトで有料（$20/月）。**100サイト規模でも月5,000円程度で収まります。**

### 設計上の注意：Resendのドメイン制限

無料プランは登録できる送信ドメインが限られる。顧客ごとのドメインから送ろうとすると上限に当たる。

→ **問い合わせ通知は自社ドメイン（noreply@{{自社ドメイン}}）から送り、Reply-Toを顧客に設定する。**
顧客ドメインごとのSPF/DKIM設定が不要になり、**我々のドメインで認証を正しく設定したほうが、むしろ迷惑メール判定されにくい。**

Claude Opus 5：入力 $5 / 100万トークン、出力 $25 / 100万トークン。

| 項目 | 量 |
|---|---|
| ページ数 | 12ページ |
| 1ページあたり入力 | 25,000トークン（ヒアリングJSON＋取材の文字起こし＋指示を含む） |
| 1ページあたり出力 | 2,500トークン |

| **合計** | **入力90万トークン／出力9万トークン ＝ 約1,500円** |

**制作費98万円に対して 0.15%。** 誤差の範囲です。

> **安いモデルに落として節約しません。** 原稿の質そのものが我々の商品です。
> 1件あたり千円程度の差のために、商品の中身を落とす判断は割に合いません。
> プロンプトキャッシュを効かせればさらに下がりますが、上記は**キャッシュなしの保守的な見積**です。

## 5. 課金モデルを変えると何が起きるか

原価は問題ありません。**問題は売上の天井です。**

### 前提

- 制作単価 98万円
- **週15時間の制約から、制作は年5〜7件が上限**（`05-資金計画と稼働設計.md` 第3章）
- 都度型：1サイトあたり年2回の更新依頼 × 1.5万円と仮定
- ストック型：制作した顧客の7割が月5万円で継続契約

### 3年シミュレーション

| | 年1 | 年2 | 年3 | 3年累計 |
|---|---|---|---|---|
| **ストック型**（当初計画） | 580万 | 1,116万 | **1,526万** | **3,222万** |
| **都度型**（今回のご要望） | 495万 | 711万 | **736万** | **1,942万** |
| 差 | 85万 | 405万 | **790万** | **1,280万** |

### なぜここまで差がつくのか

**制作件数の上限が、時間で固定されているからです。**

年7件 × 98万 = **686万。これが都度型の理論上の天井**で、3年目以降も変わりません。
しかも毎年ゼロから7件を取り直す必要があるので、**営業を永久に止められません。**

ストック型なら、3年目には運用売上840万が営業を止めても入り続ける。
**時間の上限が決まっている事業では、ストック収益がないと売上が低い位置で固定されます。**

### もうひとつ、金額より怖いこと

**更新が有料だと、顧客は依頼しなくなります。**

```
更新が有料 → 頼まなくなる → サイトが古びる → 成果が出ない
　→「作ったけど意味なかった」→ 紹介が出ない → 次の案件が来ない
```

`08-営業DM文面と想定問答.md` に「頼みづらくて放置」が解約の典型と書きましたが、
**都度課金はその「頼みづらさ」を制度として組み込むことになります。**

北九州の中小製造業は横の繋がりが強く、**紹介が最大の営業チャネルです**（`12` 第3章）。
「作ってもらったけど、あれ以来そのまま」と言われる状態を作るのは、営業的に高くつきます。

### そして監視の問題

`10-インフラとアフターフォロー方針.md` 第3章で、**フォームの疎通監視は絶対に外さない**と決めました。
問い合わせが実は届いていなかった、というのが唯一の信用失墜事故だからです。

**都度課金だと、監視契約のない顧客は監視されません。** 事故が起きたとき、
「保守契約がなかったので」は顧客にも紹介先にも通りません。

## 6. 社長としての提案：折衷案C

ご要望の「継続的な固定費を取らない」は維持しつつ、上の3つのリスクを潰す形です。

### 案C：課金はしない。ただし監視とレポートは無償で続ける

```
　保守の月額　　　　　　　　なし（ご要望どおり）
　更新作業　　　　　　　　　都度課金（1回 15,000円〜／時間単価 10,000円）
　─────────────────────────────────────────────
　死活監視　　　　　　　　　無償で継続
　フォーム疎通の週次テスト　無償で継続
　ドメイン・SSL期限の管理　 無償で継続
　月次レポートの自動送付　　無償で継続
```

**これらの原価は実質ゼロです**（第2章・第3章のとおり、監視もレポート生成も無料枠と自動化で賄える）。

**無償で出す理由は、善意ではなく営業です。**

> 毎月レポートが届く ＝ **顧客との接点が切れない。**
> 接点があれば、更新依頼も、追加案件も、紹介も出てくる。

**原価ゼロの接点維持装置**として使う。都度課金モデルでも、これがあれば第5章の
「サイトが古びて紹介が止まる」連鎖を止められます。

### 案A（もし将来考えが変わったら）：薄い維持費＋都度課金

```
　維持費　　月額 3,000〜5,000円（監視・障害対応・期限管理のみ）
　更新作業　都度課金
```

月3,000円なら「毎月取られている」感が出にくく、監視の責任も明確になります。
**今は案Cで始めて、顧客の反応を見てから案Aを検討するので十分**だと考えます。

### 案B：年額一括

月額より心理的抵抗が小さく、請求も年1回で事務が楽。「保守料 年30,000円」。
どうしても継続課金を入れたくなったときの選択肢として記録しておきます。

## 7. 私の意見（一度だけ申し上げます）

**原価の観点では、都度型で何の問題もありません。** 会社は潰れません。

ただ、`01-事業計画_v0.md` でKGIをMRRに置いたのは、**週15時間という制約下では、
ストック収益がないと売上が686万で固定されるから**でした。第5章の試算のとおりです。

もうひとつ。**WordPressを撤回してAstroにした判断の価値の大半は、
「保守契約の粗利がほぼ100%で積み上がる」ことにありました**（D-009）。
都度型にするなら、その利点の一番大きい部分は使わないことになります。
※ 原価ゼロ・障害ゼロ・表示が速いという利点は都度型でも残るので、**Astroの判断自体は変わりません。**

とはいえ、これは**アドバイザーがお客様と向き合って判断されること**です。
「月額を払わせる」ことへの抵抗感は、実際に商談をする側にしか分からない感覚だと思います。

**ご要望どおり都度型で設計を進めます。** 案C（監視とレポートは無償で継続）を推奨します。
第5章の数字は、判断の材料としてここに残しておきます。
