# 第6.5段階 — 表現は、理由なく内容を消してはいけない

**きっかけ**：第6段階の画面確認で、加工事例が4件ある会社の一覧ページに
**事例が1件も出ていない**ことが分かった。

```
data-content="cases" data-presentation="quote"   ← 4件あるのに引用1つ
```

しかも**このページでは「すべて見る」の導線も出ない作り**だったので、
**残り3件に到達する道が1つも無かった。**

---

## 1. どの組み合わせが、複数件を1件に縮約しているか（実測）

`Present.astro` の描き方を1行ずつ読み、書き出したHTMLで数え直した。

| 内容 | 表現 | 画面に出るもの | 縮約 |
|---|---|---|---|
| 加工事例 | `cardGrid` | 全件（6件超は導線） | — |
| | `spec` | 全件 | — |
| | `process` | **代表1件の3工程** | **1件** |
| | `quote` | **1発言** | **1件** |
| 設備 | `cardGrid` / `spec` / `list` | 全件 | — |
| | `largeNumber` | **「保有設備 7台」の1語** | **1件** |
| 取り扱い | `cardGrid` / `spec` / `list` / `longform` | 全件 | — |
| | `prose` | **名前だけ**（内容も料金も消える） | **1件** |
| 沿革 | `timeline` / `list` / `longform` | 全件 | — |
| | `prose` | **「創業 1972年」の1行** | **1件** |
| お客様の言葉 | `cardGrid` / `prose` | 全件 | — |
| | `quote` | **1発言** | **1件** |
| 対応材質 | `chips` / `list` / `spec` | 全件 | — |

**書き出したHTMLで数えた結果**（松原精機・検証用6社）：
`✗ 全部消えている` が出たのは**加工事例 × 引用の1組だけ**。
`equipment × largeNumber` などは表の上では可能だが、規則版は選んでいなかった（潜在）。

## 2. その縮約は意図的か

**両方ある。**

| 意図的 | バグ |
|---|---|
| トップページが代表1件を工程で見せ、**「すべて見る」で一覧へ送る** | **一覧そのものの帯**が1件に畳まれる |
| 事例の個別ページが、その1件だけを出す（D-301） | 縮約した先に、**残りへ到達する道が無い** |

つまり**縮約そのものは悪ではない。** 悪いのは「一覧が一覧でなくなること」である。

## 3. 意図的な省略とバグを、どう区別するか

**帯の役割で区別する。** 縮約してよいかは、内容や表現を見ても決まらない。
決まるのは「その帯が何をする帯か」である。

```ts
/** この帯は、その内容の全件を見せる帯である */
keepAll?: boolean;
```

一覧のページの一覧そのものだけに付ける。
付いていない帯（トップの代表1件、事例の個別ページ）は、これまでどおり縮約してよい。

## 4. どの層で保証するか

**3層に分ける。** 1箇所に集めない。

| 層 | 役割 |
|---|---|
| 語彙（`compat.ts` の `KEEPS`） | **その組み合わせで何件出るか**を持つ |
| 構成（`composePage`） | **この帯は一覧である**と宣言する（`keepAll`） |
| 検査（`presentation.test.mjs` / `qa:assets` 原則C） | **書き出したHTMLで数え直す** |

**いちばん大事なのは3層目である。** 語彙表は人が書くので、いつか実態とずれる。
**表を信じずに、画面で数える。**

### なぜ既存の `detail` では足りなかったか

語彙には既に `detail: 0|1|2`（どこまで画面に出るか）があり、
`keepsLess()` が**AIの乗り換えだけ**を止めていた（D-259）。穴は2つ。

1. **`detail` は表現だけの性質で、組み合わせの性質ではない。**
   `prose`（`detail: 2`）は `technique` では全文が出るが、
   **`history` では「創業 1972年」の1行**、`offerings` では**名前だけ**になる
2. **規則版そのものには効いていなかった。** 今回落ちたのは手順書（`PLAYBOOK`）の選択である

## 5. fallback の設計

**`["process", "cardGrid", "quote"]` と書き足すだけでは直らない。**
それは今回の1社を通すだけで、**同じ穴が別の勝ち筋で開く。**

入れたのは、候補を絞る条件1つである。

```
全件を見せる帯（keepAll）で、かつ2件以上あるとき
  → 1件に畳む表現を、手順書の候補からも、既定の落とし先からも外す
```

- **1件しか無いときは効かせない。** 1件の内容にとって、1件は全件である
- **AIの道にも同じ条件を当てる。** 規則版だけ直すと、Brief を使ったとき同じ穴が開く
- 禁止ではなく**候補から外すだけ**なので、止まらない（D-206の思想）

実測：加工事例の一覧は `quote` → `cardGrid`、汎用の実績は `process` → `cardGrid` になった。

## 6. 事例以外の同じ問題

### 事例が1件のとき（重複）

難加工の会社で、**「代表的な案件」と「加工事例」に同じ1件が二度出ていた。**
上の帯が課題→対応→結果まで全部出しているのに、下にもう一度同じ言葉が出る。
**1件の一覧は、一覧ではない。** 代表的な案件を出したなら、一覧は出さない。

### 事例が0件のとき（幽霊ページ）

**メニューにも sitemap にも載っていないページが書き出されていた**
（実測：9ページ書き出し・sitemap 8件）。
`cases/index.astro` だけ `getStaticPaths` を持っていなかった。
静的なページは作るかどうかを選べないので、対応可能範囲・設備一覧と同じ
`[...page].astro` の形に揃えた。URLは `/cases/` のまま。

### 潜在的なもの（いまは選ばれていない）

`equipment × largeNumber`、`history × prose`、`offerings × prose`、`praise × quote`。
**表の上では選べるが、規則版はいま選んでいない。**
`KEEPS` に記録したので、一覧の帯で選ばれることは無くなった。

## 7. 検査への追加

| 追加先 | 件数 | 何を見るか |
|---|---|---|
| `presentation.test.mjs` | 31 → **65** | `KEEPS` と可否表の整合／**事例が2件以上あるとき、一覧ページで全件が読める**（6社 × 全15勝ち筋）／1件のとき帯が重複しない／0件のときページを作らない |
| `qa-assets.mjs`（原則C） | 新設 | **書き出したHTMLで数え直す。** 複数件ある内容が、サイトのどこかで全件読めるか |

### 検査そのものを直した

最初の検査は「`keepAll` が付いた帯が全件を保てているか」を見ていた。
**旗そのものを外したら、見る帯が無くなって緑のまま通った。**
守るべきなのは旗ではなく**結果**なので、
「2件以上ある事例が、一覧ページで全件読めること」に書き換えた。
壊して赤くなることを確かめてある。
